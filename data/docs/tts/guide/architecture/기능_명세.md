# Qwen3-TTS 기능 명세 (Feature Specification)

> 버전: v0.9.x | 기준일: 2026-05-28 | 통합본 (기능명세서 + 03_기능명세서 머지)

vLLM(GPU) + Supertonic(CPU/ONNX) 듀얼 엔진 + 32개 언어 음성합성 플랫폼의 모든 기능을 정의한다. 시스템 아키텍처는 [`시스템_개요.md`](./시스템_개요.md) 참조.

---

## 1. 시스템 개요

| 항목 | 내용 |
|---|---|
| 기반 모델 | Qwen3-TTS-12Hz-0.6B-Base (vLLM), Supertonic-3 ONNX (CPU) |
| 지원 언어 | 32개 (vLLM 10개 + Supertonic 전용 22개) |
| 합성 방식 | 실시간 스트리밍 (WebSocket / HTTP Chunked) + 배치 |
| 캐시 구조 | Redis (기본 TTL 1시간, 히트 시 TTFB <50ms) |
| 배포 단위 | Docker Compose 멀티컨테이너 |

## 2. 핵심 기능

### 2.1 음성 합성 엔드포인트

| 기능 | 설명 | 경로 |
|---|---|---|
| WebSocket 스트리밍 | 실시간 PCM 스트리밍, 최저 지연 | `WS /v1/tts/synthesize/ws` |
| HTTP 스트리밍 | Chunked WAV 스트림 | `POST /v1/tts/synthesize/stream` |
| 배치 합성 | 전체 WAV/MP3/OGG/FLAC 파일 반환 | `POST /v1/tts/synthesize` |

### 2.2 멀티 엔진 동적 라우팅 + LAC 로드밸런서

#### 엔진 자동 판별
1. **voice_id 기반**: `supertonic_*` 접두사 → Supertonic 라우팅
2. **language 기반**: vLLM 미지원 22개 언어 → Supertonic
3. **Circuit Breaker fallback**: vLLM CB OPEN 또는 VRAM 포화 → 자동 Supertonic 전환 (`X-Engine-Fallback: true` 응답 헤더). **단, `qwen_st_*` voice만 fallback 대상** — `qwen_st_f1` → `supertonic_f1` 형태로 성별/음색 일관 매핑. 그 외 voice(`qwen_zh/ja/cv` 등 비한국어 voice)는 Supertonic이 지원하지 않아 fallback skip → vLLM 503 반환.
4. **기본값**: vLLM (10개 핵심 언어)

#### 언어 자동 감지 (v0.9.0 라이브러리 확장)
- **감지 엔진**: `tinyld` n-gram 라이브러리 (~30KB). 이전 정규식 6개 언어 → **32개 전체**
- **UI**: 드롭다운 최상단 "🌐 자동 감지" 항목 (Papago/DeepL 패턴)
- **동작**:
  - Auto 모드: 250ms 디바운스 감지 → 트리거 라벨 `🌐 자동 감지 · {언어}` 인라인 갱신
  - Manual 모드: 사용자 선택값 강제
- **실패 처리**: 신뢰도 < 0.15 또는 너무 짧은 입력 시 null → 현재 설정 유지 + `synthAutoDetectFailed` 토스트
- **백엔드 reconcile**: `engines/vllm_stream.py`의 `_detectAndReconcileLanguage`가 합성 직전 텍스트와 불일치 시 재보정
- **persistence**: `localStorage.tts_auto_detect_lang` (true/false). 미설정 시 글로벌 `default_auto_detect_lang` 적용

#### LAC (Least Active Connections)
- vLLM 워커 HA 시 Redis `vllm:lac:{ip}:{port}` 카운터 기반 최소 연결 워커 선택
- 원자성: `LUA_PICK_AND_INCR` 스크립트로 race condition 방지
- Redis 장애 시: 라운드-로빈 폴백

### 2.3 배압 제어 (Backpressure) + Circuit Breaker

#### 분산 세마포어 배압 (Hysteresis)
- `TTS_BACKPRESSURE_THRESHOLD_OPEN` (확정 56 · close 44 — 상향 시 TTFB 폭증 실측): 초과 시 503 또는 supertonic 폴백 라우팅(fallback_enabled 기본 ON)
- `TTS_BACKPRESSURE_THRESHOLD_CLOSE` (기본 30ch × GPU): 회복 시 차단 해제

#### Supertonic 우회
- CPU 기반이라 vLLM VRAM 세마포어 대상 외
- vLLM 503 상태에서도 Supertonic 정상 합성 가능
- WS 핸드셰이크는 엔진 판별 전이라 일시적 전역 검사 수행

#### 가중 활성 채널 계산
```
Weighted_Active = Active_Streams + (Active_Batches × 2.0)
_capped_active  = min(Active_Streams, 20)   # stale telemetry 가드 (10s 지연 시)
```

#### Circuit Breaker
- 연속 3회 실패 → `OPEN` 전환 + 60s 격리 → 자동 복구
- 수동 복구: `POST /v1/admin/circuit-breaker/reset`

### 2.4 음성(Voice) 관리

| 기능 | 설명 |
|---|---|
| 내장 음성 시딩 | `config/voices.yaml` 기준 DB 증분 시딩 (재시작 시 미등록 음성 자동 추가) |
| 커스텀 음성 등록 | WAV 업로드 → ref_audio 등록 → ICL 활성화 |
| 활성화/비활성화 | 관리자 UI에서 즉시 적용, 비활성화 시 합성 요청 차단 |
| 음성 클로닝 (ICL) | 레퍼런스 오디오 prefix 직접 주입, 언어 필터 설정 가능 |
| Supertonic 스타일 | M1~M5(남성), F1~F5(여성) 프리셋 |

### 2.5 텍스트 전처리 파이프라인

#### 11개 도메인 ITN (Inverse Text Normalization)
- **도메인**: standard / finance / casual / commerce / mobility / aicc / media / tech / healthcare / education / game
- **신규 패턴 (v0.8.0)**:
  - 서수 `N번째` → 첫/두/세/스무 번째, `N째` → 첫째/둘째/열째
  - 세대 표현 `2030 청년` → 이공삼공 청년 (40+ 컨텍스트 키워드)
  - 한글 월 특수: 6월=유월, 10월=시월
  - 한국 주소 dash 보존: 동/리/가/구/면 컨텍스트 + N-N → "N의 N"
  - 시간 HH:MM:SS 옵셔널 SS, 13~24시 sino 발음
- **finance 확장**: KOSPI200, KODEX200, NIKKEI225, 신한카드 등 50+ index/etf/card 항목
- **스포츠 추가 패턴**:
  - 스코어 `3-0` → "삼 대 영", `2-1` → "이 대 일" (한 자리 숫자 2개 하이픈 연결)
  - 전술 포메이션 `4-4-2` → "사 사 이", `4-2-3-1` → "사 이 삼 일" (한 자리 숫자 3개 이상 하이픈 연결)
  - 스포츠 단위어 고유어 수사 추가: 경기/골/이닝/세트 → 고유어 (`8골` → "여덟 골"), 라운드/홈런/포인트/마일리지 → 한자어 (`4홈런` → "사 홈런")
- **AICC 추가 패턴**:
  - 접수/주문/고객번호 등 키워드 + 숫자 → digit-by-digit (`주문번호 12345` → "주문번호 일이삼사오")
  - 카드번호 4-4-4-4 선처리 → digit-by-digit (대시 → "마이너스" 오변환 방지)
  - 대표전화 `1577-xxxx` / `1588-xxxx` 등 선처리
- **괄호 제거 ITN**: 모든 변환 후 최종 단계에서 잔존 `()` 괄호 제거 (TTS 모델이 괄호를 ~2초 포즈로 읽는 오동작 방지)
- **운영 자동 학습**: `pipeline/itn_unmatched.py` — 변환되지 않은 영문 토큰 자동 수집(워커별 PID 파일 + Redis Pub/Sub), Admin UI `UnmatchedPanel`에서 빈도순 등록/무시
- **회귀 테스트**: `tests/itn/golden.json` 101 케이스 24개 카테고리 prefix
- **Copy-on-Write 교체**: 런타임 규칙 수정 시 `asyncio.Lock` 가드 내 복제+빌드+원자 교체 → 구동 중 세션 영향 없음
- **상세**: [`../engine/ITN_명세.md`](../engine/ITN_명세.md)

#### 5단계 Sentence Splitter
1. **문장 부호**: `.` / `?` / `!` / 전각 `。？！` 1차 분할 (라틴 `.?!`는 뒤 공백 필수 — 약어·소수점 보호)
2. **쉼표**: `,` / `，` / `、` 2차 분할 (max_chars 초과 문장에만 적용)
3. **Korean 연결어미 병합**: `~고/며/서/지만...` 등 연결 어미로 끝나는 절은 다음 절과 합침
4. **짧은 조각 병합**: `_MIN_FRAGMENT=60`자 미만 조각, 또는 종결 부호가 있어도 `_MIN_COMPLETE_SENTENCE=60`자 미만인 완전 문장은 인접 문장과 병합 (AR EOS 조기 발행 방지). 병합 시 선행 조각의 종결 부호를 `:` 으로 교체하여 내부 EOS 억제.
5. **강제 분할**: max_chars 초과 청크(쉼표도 없는 경우)는 `split_limit = max(limit × 0.7, 40)` 목표로 공백 기준 분할 (폴백: 하드컷)

**언어별 max_chars**: ko=100, en=300, zh=120, ja=150, vi=180

#### 발음 사전 동적 교체
- **제한**: 최대 2,000개 규칙, 단어 100자 / 발음 200자
- **적용 즉시**: `PATCH /v1/admin/pronunciation` 후 메모리 구조체 갱신 (재기동 없이 텍스트 전처리 파이프라인 주입)
- **테스트**: `POST /v1/admin/pronunciation/test` — 합성 전 단어 치환 미리보기 (`original`, `result`, `applied_rules`)

#### 끝 마침표 보강 + EOS 콜론 변환 (v0.9.8+)
- `default_ensure_terminal_punct`: 문장 끝 마침표 자동 추가 → AR EOS 조기 종료 방지
- **EOS 콜론 변환** (`prepare_engine_sentence`): 후행 `.`/`。` → **`::`** (콜론 2개)로 정규화
  - 실측: `:` 1개 → 잘림, `::` 2개 → 안정 (사용자 청취 검증), `:::` 3개 → hallucination guard 발화 (과잉)
  - `_BOUNDARY_RE`: 라틴 `.?!` 공백 필수 → `e.g.`, `co.kr`, `U.S.A.`, `3.14` 등 약어/도메인 보호
  - CJK 종결부호에 `:` 추가 → 사용자가 콜론으로 끝맺어도 `.` 자동 추가 안 됨

### 2.6 오디오 후처리 (v0.9.8 default 갱신)

| 기능 | 설명 | 기본값 |
|---|---|---|
| 무음 패딩 (앞) | 재생 시작 시 팝음 방지 | **200ms** (단축 500→200) |
| 무음 패딩 (뒤) | trailing padding — silence_guard ON 환경 짧게 | **250ms** (단축 1500→250) |
| 마이크로 페이드 | 청크 경계 팝음 제거 | ON |
| Tail cosine fade-out | 끝 부드러운 페이드 | 200ms |
| 무음 가드 (silence_guard) | RMS 임계 trailing 무음 감지·자동 stop | **ON** (단축 OFF→ON) |
| Silence 임계 (max_silence_ms) | guard 발화 임계 | **700ms** (단축 3000→700) |
| Silence hangover | 카운트 전 유예 (vocal pause 보호) | **300ms** (단축 500→300) |
| Hallucination guard (max_sentence_audio) | 1문장당 최대 audio 길이 | **30s** (단축 60s→30s) |
| 문장 사이 정적 (inter_sentence_padding) | 구두점 기반 자동 스케일 | **120ms** (단축 500→120) |
| 초성 보존 룩백 | Lookback 버퍼 → 무음 가드 작동 시 초성 보존 | ON |
| 고음질 모드 | 주파수 보간 + 선명도 강화 | ON |
| 스마트 억양 | 구두점 기반 억양 자동 조절 | ON |
| DSP 프로파일 | standard / phone_line / small_speaker / studio | standard |

#### 끝 잘림 방지 보강 (v0.9.0)
- **silence guard 보강**: vLLM borderline RMS chunk(자음 감쇠) 음성 꼬리 보존 — break 직전 `yield current_chunk` 추가 (`engines/vllm_stream.py:307-310`)
- **trailing_silence_ms**: 합성 chunk 루프 종료 후 N ms 무음 PCM 추가 yield → decoder/player flush 안정화
  - 적용: vLLM 24kHz, Supertonic in-process 44.1kHz, Supertonic 워커 (remote)
  - per-call override: body의 `trailing_silence_ms`로 요청별 조정, 0 = 비활성

### 2.7 캐싱

- **키**: 엔진·텍스트·음성·속도·temperature·top_p·ITN·ICL·언어·DSP 파라미터 해시
- **TTL**: 기본 1시간 (관리자 설정 가능)
- **히트 응답**: <50ms TTFB
- **Pre-cache**: 관리자가 특정 문장 미리 합성하여 캐시에 적재

### 2.8 통일 로그 포맷

- **규격**: `HH:MM:SS | LEVEL | source | message`
- **Level**: INFO / DEBUG / WARNING / ERROR / CRITICAL
- **Source**: api / vllm-a / vllm-b / fast / redis / postgres / nginx
- **파서**: Nginx (ISO 8601) / PostgreSQL (`log_line_prefix='%t | %l | postgres | [%p] '`) / Redis 포맷을 표준으로 실시간 변환
- **시간순 병렬 머지**: `GET /v1/admin/logs/source/all` — 각 컨테이너 로그를 병렬 fetch + 타임스탬프 정렬 + 단일 스트림 뷰

### 2.9 동적 다국어 시딩 + Named Volume 자가 복구 (v0.9.5)

- **DB 증분 시딩**: 기동 시 `/app/config/voices.yaml` 스캔 → 관리자 변경 음성·사용자 지정 음성 보존 + 신규 다국어 프리셋(중국어/일본어 등) 안전 삽입
- **Named Volume 자가 복구**: `/app/config/samples/`와 `/app/voices_data/samples/` 비교 → 누락된 음원(.mp3) 자동 복사 동기화 → 관리자 수동 업로드 없이 무중단 기동 보장

- **CSV export 12개 컬럼**: Timestamp/User/Engine/Voice/Text/Language/Speed/Temperature/TTFB(ms)/Latency(ms)/CER/Options(JSON). UTF-8 BOM, Excel 한글 호환

- 할당량 관리 (메모리 MB 단위)

### 4.8 Precache 탭 (사전 캐시)

- **프리셋 불러오기**: 기본 한국어 인사말 세트(안녕하세요·감사합니다 등)를 편집 가능한 textarea에 프리필 → **음성 멀티선택**(체크박스) → `문장 × 음성` 조합 일괄 등록
- 특정 문장 단건 사전 합성 등록 (문장·음성·언어·속도)
- 배치 캐시 채우기 Job 실행 + 진행률(done/skipped/failed) 표시
- **적용 범위**: 캐시는 문장 단위 + text 전체 해시 키라 **고정·반복 문구**(챗봇 정형 응답, 안내/ARS 대사)에만 효과. `"안녕하세요 {이름}입니다"` 같은 변수 문장은 무효(공백 미분리 + 짧은 인사말은 뒤 문장과 병합돼 매번 다른 키)
- **영구 유지**: 등록·합성된 캐시는 무TTL 영구 저장, 메모리 퍼지에서 제외 (상세: [REST 명세 §5.8](../api/REST_명세.md))

### 4.9 Feedback 관리 탭 (Admin)

- 사용자 품질 피드백 그리드 목록 (최신순)
- 필터: 처리 상태(`open`/`reviewed`/`resolved`), 사용자명
- 처리 상태 변경 (`open → reviewed → resolved`)
- trace_id 클릭 → 해당 audit_logs 행 대조
- 피드백 삭제

## 5. 엔진별 통계 및 진단 (v0.8.0~)

### 5.1 통합 엔진 진단 API
- **엔드포인트**: `GET /v1/admin/debug/engines/diagnostics`
- **동작**: vLLM(a/b) + Supertonic을 `asyncio.gather` 병렬 health-check
- **응답**: 엔진별 status/warmup/addrs/latency 통합
- **UI**: Admin 대시보드 진단 탭 엔진 카드

### 5.2 엔진별 추이 통계
- **백엔드** (`GET /v1/admin/stats/summary`): `usage_trend_by_engine`, `latency_trend_by_engine`, `cer_trend_by_engine`, `voice_popularity_by_engine`, `cer_by_engine` (v0.9.0 신설 — 엔진별 평균 CER + 샘플 수)
- **프론트 시각화**: 일별 사용량/지연 P95/CER 차트에 vLLM·Supertonic 점선 라인 분리
- **엔진별 KPI 카드** (v0.9.0): 엔진 1개당 카드 — 요청 수(점유%) · 평균 latency · 평균 CER 등급
  - 등급 색상: `<2% 우수 / <5% 양호 / <15% 보통 / 그 이상 불량`
- **측정 히스토리**: MeasurePage `spansToLatRec`에 `engine` 인자 추가 → 엔진별 P50/P95 비교

### 5.3 워밍업 추적
- **Redis 키**: `warmup:status:vllm`, `warmup:status:supertonic` 분리 → 다중 워커 중복 워밍업 방지
- **헬스 응답**: `engine_warmup: {vllm: ok|pending, supertonic: ok|pending}` — 부분 가용성 가시화

## 6. 시스템 안정성

| 기능 | 설명 |
|---|---|
| Circuit Breaker | 3회 실패 → 60s 격리 → 자동 복구, vLLM CB OPEN 시 Supertonic 자동 전환 |
| Backpressure | VRAM 점유율 임계 초과 시 신규 요청 대기/거부 |
| Emergency Stop | 긴급 합성 전체 중단 |
| Rate Limiting | IP/사용자별 시간당 요청 제한 (Redis 카운터). Redis 장애 시 워커-로컬 인메모리 폴백(auth·synthesize)으로 fail-open 방지 — me.py benchmark 만 fail-closed(503) |
| 비활성 타임아웃 | 사용자 비활동 N초 후 자동 세션 만료 |
| 동시성 제한 | stream/batch 별도 세마포어 |
| 롤링 업데이트 | `deploy-roll.sh` — vLLM 무중단, API+프론트만 교체 |
| **DB 풀 모니터링** | `pool_size`, `checked_out`, `overflow` 수집. utilization 80% 초과 시 warning |
