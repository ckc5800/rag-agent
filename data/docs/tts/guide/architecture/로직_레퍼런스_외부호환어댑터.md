## 변환 규칙 대조

두 어댑터가 외부 필드를 네이티브 `SynthesizeBody`로 바꾸는 규칙. **`services/tts/voice_alias.py` 별칭 정규화는 공통 의존.**

| 외부 필드 | 네이티브 | 변환 위치 | 비고 |
|---|---|---|---|
| `input`(OpenAI) / `text`(AIVOX WS) | `text` | 직접 | — |
| `voice`(HTTP) / `speaker`(WS) | `voice_id` | `voice_alias.to_internal()` | 공개별칭(F_ko_bright)→내부ID. 안 하면 목록 응답값을 그대로 넣어도 lookup 실패 |
| `language`("Korean"/"Auto") | `language`(ISO 또는 None) | `_normalize_language()` | "auto"·""→None(자동감지 위임). 미매핑은 원본 전달(Supertonic 21개 코드는 ISO 동일) |
| `task_type`("Base"/"CustomVoice") | `use_icl`(bool) | `_task_type_to_use_icl()` | Base→True, CustomVoice→False, VoiceDesign→400 |
| `response_format`(6종) | `audio_format`(4종)+strip | `_RESPONSE_FORMAT_MAPPING` | pcm→("wav", strip_header=True). opus·aac→400 |
| `emotion`("calm" 등) | temp/top_p/speed | `_apply_emotion_preset()` | 명시값 우선. "default"=no-op(서버 DB 기본값) |
| `volume`(WS만) | PCM 진폭 스케일 | `_apply_volume_to_pcm16()` | 0(음소거) 보존. int16 clip |

# Part 1 — OpenAI 호환 (HTTP)

`routers/openai_compat.py` — AIVOX/OpenAI Audio Speech 표면. 내부 `synthesize_batch` / `synthesize_stream_http`로 위임.

### 1.1 base_url만 바꿔 동작하는 호환 표면

- **무엇을**: `POST /v1/audio/speech`가 OpenAI TTS 스키마를 받아 네이티브 합성으로 위임.
- **왜/배경**: 기존 AIVOX/OpenAI SDK 사용자가 코드 변경 없이(주소·키만) 이관하도록. 신규 SDK 개발자에겐 네이티브(`/v1/tts/synthesize`) 권장 — 어댑터는 *레거시 호환*용.
- **어디서**: `openai_compat.py::aivox_audio_speech` (≈L313). 요청 모델 `OpenAISpeechRequest` (≈L156). 라우터 태그 `Legacy API`.
- **어떻게**: ①거절검사(400) → ②무시필드 경고 축적 → ③필드 변환 → ④rate limit → ⑤`stream` 여부로 batch/chunked 분기.
- **주의/함정**: `OpenAISpeechRequest`는 OpenAI 표준 필드 + **신규 고급 옵션**(temperature/top_p/use_itn/supertonic_* 등)을 모두 받는 **초집합**이다. 순수 OpenAI 클라이언트는 표준 필드만 쓰고 나머지는 기본값(None)으로 흘러 시스템 default가 적용된다.

### 1.2 인증 이중 허용 (X-API-Key ‖ Authorization)

- **무엇을**: `X-API-Key: sk-...` 또는 `Authorization: Bearer <JWT|API Key>` 둘 중 하나 허용.
- **왜/배경**: AIVOX는 `X-API-Key`, OpenAI SDK는 `Authorization: Bearer`. 둘 다 받아야 양쪽 클라이언트가 무수정 동작.
- **어디서**: `openai_compat.py::_resolve_compat_user` (≈L215). 내부적으로 `core.security.get_current_user`로 위임.
- **어떻게**: x_api_key 우선 → 없으면 authorization에서 "Bearer " 접두 제거 → 토큰 없으면 인증모드별 분기(solo/team=우회, public=401).
- **주의/함정**: 인증 헤더 파라미터는 **public 모드에서만 스웨거 노출**(`_SHOW_AUTH_HEADERS`, ≈L212) — secret/solo/team 배포에선 토큰 인증을 안 써 빈 파라미터가 무의미했다. 노출 여부만 다르고 기능은 모드 무관 동일.

### 1.3 response_format → audio_format + PCM 헤더 strip

- **무엇을**: 6종 요청 포맷을 네이티브 4종 + PCM 특수처리로 매핑.
- **왜/배경**: 네이티브는 wav/mp3/ogg/flac만. PCM은 별도 포맷이 아니라 **wav 합성 후 RIFF 헤더(44B)를 벗긴 raw**로 제공해야 AIVOX PCM 클라이언트가 받는다. opus·aac는 미지원 → 조용히 깨지는 대신 400으로 명확 거절.
- **어디서**: `_RESPONSE_FORMAT_MAPPING`(≈L80) → `("wav", True)`가 pcm. strip은 `_strip_wav_header`(≈L261). 거절은 `_UNSUPPORTED_RESPONSE_FORMATS`(≈L87).
- **어떻게**: batch 경로는 완성 wav 바이트에서 헤더 제거 후 `application/octet-stream`으로 재포장(≈L472). stream 경로는 iterator를 감싸 **첫 44B 이상 누적 후** 헤더만 strip(`_pcm_iter`, ≈L435).
- **주의/함정**: **PCM은 WAV 헤더가 없으므로 샘플레이트를 `X-Sample-Rate` 헤더로 전달** — 클라이언트가 이 값으로 디코딩해야 한다(24000/44100/48000 가변). 스트리밍 헤더 strip은 TCP 단편화로 헤더가 여러 청크에 쪼개질 수 있어 **44B 누적 후** 처리하고, 성공 시에만 버퍼 클리어(M4 수정). `_strip_wav_header`는 항상 bytes 반환 → 옛 `is not None` 분기와 4KB fallback은 dead code라 제거됨.

### 1.4 stream + 압축포맷 → 비스트리밍 폴백

- **무엇을**: `stream=true`인데 response_format이 mp3/flac/ogg면 스트리밍을 끄고 단일 응답으로 폴백.
- **왜/배경**: 진짜 스트리밍 인코딩(청크별 mp3)이 미구현이라, 그대로 흘리면 WAV가 나가 Content-Type과 실제 바이트가 어긋난다. 정확한 포맷 보장이 스트리밍보다 우선.
- **어디서**: `aivox_audio_speech` 내 `_can_stream = bool(body.stream) and audio_format == "wav"` (≈L417).
- **어떻게**: wav/pcm만 진짜 스트리밍(pcm은 매핑상 audio_format=="wav"). 압축포맷은 폴백하며 `X-Compat-Warning`으로 안내.
- **주의/함정**: pcm이 스트리밍 가능한 이유는 내부적으로 wav로 합성하기 때문 — 매핑을 audio_format 기준으로 봐야 하고 response_format 기준으로 보면 안 된다.

### 1.5 emotion 프리셋 병합 (명시값 우선)

- **무엇을**: `emotion`(energetic/soft/calm/whisper)을 temperature/top_p/speed 3값으로 확장.
- **왜/배경**: 외부 개발자가 세 파라미터를 몰라도 감정 단축키로 운율 조정. 명시값이 함께 오면 그 값이 이기게 해 **가장 예측 가능한 동작** 보장.
- **어디서**: `_EMOTION_PRESETS`(≈L96) + `_apply_emotion_preset`(≈L104).
- **어떻게**: emotion 없거나 "default"면 no-op(서버 DB 기본값 적용). 프리셋 있으면 명시되지 않은(None) 필드만 프리셋으로 채움.
- **주의/함정**: 현재 엔진이 Qwen3-TTS **Base**라 자연어 `instructions`는 설계상 거의 무시(화자 임베딩 복제). 감정 조정은 `instructions`가 아니라 `emotion`/temperature로 해야 실제 효과가 있다 → [[qwen3-tts-base-no-emotion]].

### 1.6 voice 사전검증 (M8) & 404 친절 변환

- **무엇을**: OpenAI `voice`엔 패턴 제약이 없지만 `SynthesizeBody.voice_id`는 `^[A-Za-z0-9_\-]*$`/max 64 강제 → 위반 시 사전 422.
- **왜/배경**: 검증을 SynthesizeBody 생성자에 맡기면 핸들러 내부 ValidationError가 일반 핸들러로 흘러 **HTTP 500**을 반환했다(M8). 사전 검사로 422 명확 반환.
- **어디서**: 사전검증 `aivox_audio_speech` 내 정규식(≈L361). 404 변환은 except 블록(≈L485).
- **어떻게**: voice 길이/문자 검사 → 통과 시 `to_internal` 정규화 → SynthesizeBody 구성. 하류 404/voice-not-found는 "Voice '{voice}' is not available"로 재포장하고 `_audit_synthesis_failure`로 감사.
- **주의/함정**: 실패 시 모든 경로에서 `_audit_synthesis_failure`를 부른다(404/기타 HTTPException/Exception 3분기) — 감사 누락 방지.

### 1.7 GET /v1/audio/voices — 공개 목록 대칭

- **무엇을**: OpenAI 형식(`{object, data}`)으로 voice 목록 반환. `id`를 speech의 `voice`에 그대로 사용.
- **왜/배경**: 클라이언트가 목록 조회 → 합성을 같은 id 체계로 하게. 네이티브 `/v1/voices`와 **동일 카탈로그**여야 목록에 있는 id가 합성에서 404 안 난다.
- **어디서**: `openai_compat.py::aivox_list_voices` (≈L563). 준비검사 `routers.voices._voice_ready_meta`(≈L598). 별칭 `to_public`.
- **어떻게**: DB voice registry 로드 → enabled=false·미준비(ref_audio 없음) 제외 → engine/language/ws_only 필터 → `to_public(vid)`로 공개별칭 노출.
- **주의/함정**: `id`는 반드시 **`to_public`**으로 내보내고 speech에선 **`to_internal`**로 되돌린다 — 내부ID를 노출하면 두 공개 목록(`/v1/voices` vs `/v1/audio/voices`)이 divergent 카탈로그를 반환하는 버그가 났었다. 엔진 추론은 `_infer_engine`: meta.engine 우선, 없으면 `supertonic_` 접두사 → [[engine-from-voiceid-prefix]].

# Part 2 — AIVOX 호환 (WebSocket)

`routers/aivox_ws_compat.py` — AIVOX `/ws/tts` 프로토콜. 내부 `services.tts.websocket.synthesize_stream`으로 위임. `include_in_schema=False`(스웨거 비노출).

### 2.1 어댑터 패턴 — 가짜 WebSocket으로 send 가로채기

- **무엇을**: 네이티브 `synthesize_stream(websocket, ...)`이 부르는 `send_bytes`/`send_text`를 가로채 AIVOX 포맷으로 변환.
- **왜/배경**: 네이티브 WS 메시지 포맷(`{status: "done", ...}`)과 AIVOX 포맷(`{type: "tts.end", ...}`)이 다르다. 합성 코어를 건드리지 않고 **출력만** 변환하려면 WS를 감싸는 어댑터가 최소 침습.
- **어디서**: `aivox_ws_compat.py::_AivoxAdapter` (≈L93). 네이티브 진입 `services/tts/websocket.py::synthesize_stream`.
- **어떻게**: `_AivoxAdapter(real_ws, volume)`를 진짜 WS 대신 `synthesize_stream`에 주입. send_bytes→PCM 재정렬/변환, send_text→상태메시지 변환. client_state/scope 등은 property 패스스루.
- **주의/함정**: 어댑터는 `synthesize_stream`이 접근하는 속성(client_state/application_state/scope/client)을 모두 패스스루해야 한다 — 하나라도 빠지면 코어가 AttributeError로 죽는다.

### 2.2 PCM 9,600 bytes(200ms) 재정렬

- **무엇을**: 가변 크기 네이티브 PCM 청크를 **정확히 9,600 bytes**(4,800 samples, 200ms @ 24kHz/16-bit/mono) 단위로 재정렬.
- **왜/배경**: AIVOX 명세가 200ms 고정 청크를 요구. 클라이언트가 이 크기를 가정하고 버퍼링/재생하므로 어긋나면 끊김·글리치.
- **어디서**: `_AIVOX_CHUNK_BYTES = 9600` (≈L66). 재정렬 루프 `_AivoxAdapter.send_bytes` (≈L117).
- **어떻게**: 내부 버퍼에 누적 → 9,600B씩 잘라 volume 적용 후 송신. `done` 시 잔여 버퍼는 크기 제약 없이 flush(마지막 청크만 <9,600B 허용).
- **주의/함정**: `duration`은 **송신한 샘플 수 ÷ 24000**으로 계산 → 송신 실패한 청크도 `_samples_emitted`에 반영해야 오보고 안 남(M6). 홀수 바이트 PCM은 int16 정렬이 깨져 `np.frombuffer`가 ValueError → done 핸들러가 죽고 tts.end 미송신 → **클라이언트 무한대기**. 마지막 1바이트를 버려 방지(≈L77).

### 2.3 상태 메시지 변환 (started/done/error)

- **무엇을**: 네이티브 `{status}` JSON을 AIVOX `{type}` 메시지로 변환.
- **왜/배경**: `tts.start`는 첫 PCM 도착 시 1회, `tts.end`는 done 시 duration/cached/elapsed 포함해 송신 — AIVOX 클라이언트의 종료 판정 신호.
- **어디서**: `_AivoxAdapter.send_text` (≈L148). tts.start는 send_bytes 첫 호출(≈L123).
- **어떻게**: error→`{type:error}`, status∈(None/started/audio_complete/heartbeat)→무시, done→잔여flush+`{type:tts.end}`.
- **주의/함정**: send_text의 **JSON 파싱 실패를 silent drop하면 안 된다** — done/error 종료 신호를 클라이언트가 영영 못 받아 합성이 멈춘 것처럼 보인다. 반드시 로그로 노출(≈L157).

### 2.4 인증 — query param / subprotocol (WS는 커스텀 헤더 불가)

- **무엇을**: `?api_key=` → `?token=` → `Sec-WebSocket-Protocol[1]` 순으로 토큰 추출. team모드는 `?username=`.
- **왜/배경**: 브라우저 WebSocket API는 커스텀 헤더를 못 붙인다 → 인증을 query param/subprotocol로 우회.
- **어디서**: `_extract_token` (≈L241), `_extract_team_username` (≈L257). 검증은 `get_current_user(websocket, token)`.
- **어떻게**: 토큰 없고 auth.disabled면 solo=anonymous@IP/super_admin, team=username→EXTRA_ACCOUNTS lookup. 토큰 있으면 네이티브 검증. 실패 시 close(4001).
- **주의/함정**: team/solo 유저는 매 요청 fresh dict라 DB에 없다 → 네이티브 integrity check가 "deleted"로 **항상 차단**하는 버그. `_team_mode` 마커일 때 `integrity_checker=_always_ok`를 주입해 DB lookup 우회(≈L504).

### 2.5 tts.stop / 재요청 시 진행 태스크 취소

- **무엇을**: `tts.stop` 또는 새 `tts.request`가 오면 진행 중 합성 task를 cancel.
- **왜/배경**: 사용자가 중단하거나 새 문장을 보내면 이전 합성을 즉시 멈춰야 리소스·순서 보장.
- **어디서**: 메시지 루프 `aivox_ws_compat` (≈L379 tts.stop, ≈L394 재요청). 완료 콜백 `_on_aivox_synth_done`(≈L520).
- **어떻게**: `active_task.cancel()` → `wait_for(shield(task), 2.0)`. tts.stop은 `tts.interrupted` 응답.
- **주의/함정**: 취소된 task는 py3.11+에서 **CancelledError(BaseException)**로 끝난다 — `except Exception`만 잡으면 while 루프를 탈출해 **WS 전체가 붕괴**. `except (Exception, asyncio.CancelledError)`로 함께 포착해야 한다(≈L384, L398).

### 2.6 Supertonic voice 거절 (24kHz 불일치)

- **무엇을**: 내부ID가 `supertonic_`인 voice는 400 거절.
- **왜/배경**: Supertonic은 44.1kHz인데 AIVOX 클라이언트는 24kHz 가정 코드 → 샘플레이트 불일치로 재생이 깨진다. 사전 차단이 조용히 깨지는 것보다 낫다.
- **어디서**: tts.request 처리 내 `to_internal(voice).startswith("supertonic_")` (≈L429).
- **어떻게**: 공개별칭(F_ko_sua 등)도 supertonic으로 매핑되므로 **`to_internal`로 해소 후** 검사. 걸리면 vLLM voice 사용 안내 에러.
- **주의/함정**: HTTP 어댑터에는 이 제약이 없다(포맷 변환으로 흡수 가능) — WS만 24kHz 고정이라 거절한다. 이 차이가 두 어댑터의 옵션 집합이 다른 이유.

## 거절·무시 정책

| 정책 | HTTP(`/v1/audio/speech`) | WS(`/ws/tts`) |
|---|---|---|
| **400 거절** | ref_audio inline · response_format opus/aac · task_type VoiceDesign | Supertonic voice(44.1kHz) |
| **무시+경고**(`X-Compat-Warning`) | instructions · seed · n_candidates>1 | AIVOX `style` 필드(silent drop) |
| **의도적 제외 옵션** | — | audio_format·response_format·task_type·seed·n_candidates·ref_audio·supertonic_*(WS 의미상 무의미) |
| **인증** | X-API-Key ‖ Authorization Bearer | ?api_key= ‖ ?token= ‖ subprotocol[1] |

## 불변식 (깨면 외부 클라이언트가 깨진다)

1. **목록↔합성 id 대칭**: `/v1/audio/voices`가 내보낸 id는 `to_internal`로 되돌려 합성 가능해야 한다. 목록은 `to_public`, 합성은 `to_internal` — 한쪽만 바꾸면 목록에 있는 id가 404.
2. **PCM 샘플레이트는 헤더로**: PCM 응답엔 WAV 헤더가 없다 → `X-Sample-Rate` 없이는 클라이언트가 디코딩 못 한다.
3. **WS 종료 신호는 반드시 도달**: `tts.end`/`error`를 silent drop하면 클라이언트 무한대기 = 합성 멈춤으로 보인다.
4. **취소 예외 함께 포착**: WS에서 `asyncio.CancelledError`(BaseException)를 `Exception`만으로 잡으면 루프 붕괴.
5. **volume 0 보존**: 음소거(0)를 falsy로 1.0 치환하면 음소거 요청이 무시된다.
6. **9,600B 청크 고정**: 마지막 청크 외에는 정확히 200ms — 어긋나면 AIVOX 클라이언트 재생 글리치.
