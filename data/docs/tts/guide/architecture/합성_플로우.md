## 3. 텍스트 전처리

**파일**: `services/tts/common.py:process_synthesis_text()`  
**분할**: `services/tts/common_sentence.py`

```
원본 텍스트
    │
    ├─ ITN (use_itn=True, 한국어만)
    │   숫자·단위·기호 → 한국어 발음
    │   itn_domain: standard / finance / casual / ...
    │
    ├─ 문장 분할 (use_split=True)
    │   구두점 기반 + 최소/최대 길이 병합
    │   [Stream 전용] Supertonic + 150자 초과 시 → auto-enable
    │   (batch/websocket은 해당 없음)
    │
    ├─ 터미널 구두점 (use_terminal_punct=True)
    │   마침표 없는 문장에 자동 추가 → 마지막 음절 잘림 방지
    │
    └─ EOS 변환  prepare_engine_sentence()
        "이번이 처음이다. 우리가 해냈다."
         → "이번이 처음이다: 우리가 해냈다::"
        규칙:
          후행 '.' / '。' → '::'
          내부 '. '       → ': '  (소수점 '3.14' 제외)
          트리거 조건: 마침표 있음 OR 30자 이하 단문 OR '?' / '!'
```

**`calc_inter_sentence_pause(sent, base_ms)`** — 구두점별 포즈 배수:

| 마지막 문자 | 배수 |
|---|---|
| `.` `。` `!` `！` | ×1.4 |
| `?` `？` | ×1.2 |
| `;` `；` | ×0.7 |
| `,` `，` `、` | ×0.5 |
| 기타 | ×1.0 (최소 base×0.3) |

## 4. 3가지 합성 모드

### 4-A. Batch (`services/tts/batch.py`)

```
모든 문장 동시 합성 (asyncio.gather)
    │
    ├─ 문장 캐시 확인 (sentence_voice_guard_v8)
    │   히트 → 엔진 합성 생략 (DSP stitch는 동일하게 적용)
    │   미스 → 엔진 합성 → 캐시 저장
    │
    ├─ Quota 예약 (추정 바이트) → 합성 → 정산 (실제 바이트)
    │
    ├─ DSP 후처리 (stitch 단계, gather 완료 후)
    │   Micro Fade: 첫 문장 fade-in, 마지막 문장 fade-out만 적용
    │               fade_ms = min(2ms, pcm길이/4) — WS의 30/20ms와 다름
    │   Trim → Tail Fade:
    │     중간: trim(-50dB, keep=40ms) → fade(50ms)
    │     마지막: trim(-50dB, keep=100ms) → fade(trailing_fade_ms)
    │        (구 -30dB 는 한국어 끝음절 저에너지 트레일링을 잘라 -50dB 로 통일)
    │
    ├─ 문장 간 포즈 삽입 (inter_sentence_padding_ms × 구두점 배수)
    │
    ├─ stitch 후 전체 WAV DSP (use_normalize → high_fidelity → hardware_profile)
    │   normalize_audio → vocoder upscale+enhance_clarity (vLLM) / enhance_clarity (Supertonic)
    │   → AudioPostProcessor.apply_profile (hardware_profile != standard 시)
    │
    └─ 세션 캐시 저장 (batch_voice_guard_v7)
       반환: audio/wav (전체 WAV)
```

**세마포어**: `_batch_sem` (엔진별 동시 합성 수 제한)

### 4-B. HTTP Streaming (`services/tts/stream.py`)

```
세션 캐시 확인 (stream_voice_guard_v5)
  히트 → 즉시 전체 반환
  미스 → 순차 문장 처리
    │
    문장별 루프:
    ├─ 문장 캐시 확인
    │   히트 → 엔진 합성 생략 (DSP는 동일하게 적용)
    │   미스 → 엔진 스트림 (trailing_fade_ms=0.0 전달 → 엔진 tail 비활성)
    │
    청크별 처리:
    ├─ Micro Fade-in: 첫 번째 비무음 청크에만
    │   sent_idx=0 → 30ms, 이후 문장 → 20ms
    │
    ├─ DSP: Hardware Profile 필터 (상태 유지 IIR) + high_fidelity exciter
    │
    ├─ Tail Buffer → 코사인 fade (서비스 레이어, engine tail과 별개)
    │   target = (fade_ms + max_silence_ms + 100ms)  ← WS의 150/400ms와 다름
    │   중간: fade_ms=50ms, trim(-50dB, keep=40ms)
    │   마지막: fade_ms=trailing_fade_ms(200ms), trim(-50dB, keep=100ms)  ← 구 -30dB(끝음절 절단) 통일
    │
    ├─ 문장 간 포즈 (inter_sentence_padding_ms)
    ├─ 마지막 문장: trailing_silence_ms 추가
    └─ DSP 필터 상태 초기화 (문장 경계 누수 방지)

세션 캐시 저장 (stream_voice_guard_v5): 완료 후 L1 저장
```

**응답 헤더**: `X-Synthesis-Trace-ID`, `X-Queue-Ms`, `X-Inference-Ms`
*(Batch 응답: `X-TTFB-Ms`, `X-RTF`, `X-Duration-Seconds`, `X-Sample-Rate`, `X-Min-Chunk-Ms`, `X-Trace-Id`, `X-Queue-Ms`, `X-Inference-Ms`, `X-Synthesis-Trace-ID`)*

### 4-C. WebSocket (`services/tts/websocket.py`)

```
JSON: {"status":"started","sample_rate":<engine_sr>,"engine":"vllm","voice_id":"..."}
      ※ sample_rate: vLLM=24000, Supertonic=44100 (engine_sr 그대로)
    │
    문장별 루프 (_synthesize_all):
    ├─ 사용자 무결성 확인 (10초 캐시)
    ├─ JSON: {"type":"sentence_start","idx":0,"text":"..."}
    ├─ _synthesize_one_sentence()  ← 핵심 (§5 상세)

    │
JSON: {"status":"done","trace_id":"...","total_ms":...,"sentences":N,...}
```

**프로토콜 메시지 순서**:
```
→ (connect)
← {"status":"started", "sample_rate":24000|44100, "engine":"vllm", "voice_id":"..."}
← {"type":"sentence_start", "idx":0, "text":"..."}

← {"status":"audio_complete"}
← {"status":"done", "trace_id":"...", "total_ms":..., "sentences":N, ...}

```

## 5. WebSocket 청크 처리 루프 (핵심 로직)

**파일**: `websocket.py:WSSynthesisSession._synthesize_one_sentence()`

### 5-1. Tail Buffer 오토마타

두 개의 tail 크기를 사용한다:
- **중간 문장** (`is_last=False`): `150ms` — dead air 최소화
- **마지막 문장** (`is_last=True`): `400ms` — -50dB trim + 100ms keep 컨텍스트 (구 -30dB 는 끝음절 절단)

```
청크 수신 (DSP 후 processed)
    │
    ├─ _tail_early_flushed AND NOT 음성청크?
    │     Yes → EOS 패스스루 단계 (§5-2)    ← early flush 이후 경로
    │
    ├─ (공통) tail_audio_buf.extend(processed)   ← 음성·무음 모두 축적
    │   tail > 2s? → 앞부분 잘라 2s로 cap (_WS_MAX_TAIL_BUF 보호)
    │
    ├─ 음성 청크 (RMS ≥ -50dB)?
    │     Yes → _eos_consec_ms = 0           ← EOS 카운터 리셋
    │           tail > _tail_buf_target?
    │             Yes → 초과분 send_bytes    ← 무음 청크에선 해제 안 함
    │     No  → _eos_consec_ms += chunk_dur_ms
    │
    └─ NOT 음성청크 AND _eos_consec_ms >= 150ms?
          Yes → Early EOS Flush (§5-2)
```

### 5-2. Early EOS Flush (EOS 감지 시 즉시 전송)

**목적**: 600ms EOS 침묵 누적 중 발생하는 dead air 제거

```
_eos_consec_ms >= 150ms (= silence_hangover(100ms) + 50ms 여유)
    │
    ▼
trim_trailing_silence(tail_buf)
    마지막 문장: threshold=-50dB, keep_ms=100ms  (구 -30dB → 끝음절 절단으로 통일)
               결과 완전 무음 시 fallback: -40dB → -50dB/keep0
    중간 문장:  threshold=-50dB, keep_ms=50ms
    │
    ▼
apply_tail_fade_cosine(trimmed)
    마지막 문장: fade_ms = min(trailing_fade_ms, 200ms)
    중간 문장:  fade_ms = 50ms
    │
    ▼
send_bytes(faded)
_tail_audio_buf.clear()
_tail_early_flushed = True
    │
    ▼
이후 EOS silence 처리:
    마지막 문장 → 직접 전송 (trailing 무음이므로 자연스러움)
    중간 문장  → 드롭  (inter_sentence_padding이 포즈 역할)
```

**Dead air 계산 (중간 문장)**:

```
dead_air ≈ tail_size(150ms) + EOS_threshold(150ms) - client_buffer(50ms)
         ≈ 250ms

기존 (tail=400ms, EOS sent):  ~1030ms silence between sentences
개선 (tail=150ms, EOS drop):  ~450ms  silence between sentences
```

### 5-3. Micro Fade-in

**조건**: `use_micro_fade=True` + 첫 번째 실제(비무음) 청크만

```python
fade_in_ms = 30.0  # is_first_sentence
fade_in_ms = 20.0  # 이후 문장
apply_micro_fade(chunk, sr, fade_ms, fade_in=True)
```

### 5-4. DSP 처리 (`_dsp`)

```
raw PCM chunk (StreamingAudioProcessor — 상태 유지 IIR)
    │
    ├─ Hardware Profile 필터
    │   standard   → 패스스루 (is_passthrough=True, to_thread 없음)
    │   phone_line → 4차 BPF 300-3400Hz + 1.2× gain
    │   small_sp.  → 4차 HPF 150Hz (서브베이스 제거) + 1.1× gain
    │   studio     → adaptive 컴프레서 (peak 추적 + tanh soft-knee)
    │
    └─ (high_fidelity=True) → 6kHz HP 필터 + Harmonic Exciter (mix=0.06)
                               ※ WS/Stream: 스트리밍 인라인 적용, 업샘플 없음
                               ※ phone_line + high_fidelity → Exciter 생략 (BPF와 충돌, profile != phone_line 조건)
                               ※ Batch vLLM: 별도 vocoder_bridge로 24kHz→48kHz 후 enhance_clarity
                               ※ Batch Supertonic: enhance_clarity만 (이미 44.1kHz)
                               ※ Batch 적용 순서: high_fidelity → hardware_profile (WS/Stream 반대)
```

## 6. 엔진 계층 — vLLM 청크 처리

**파일**: `engines/vllm_chunk.py`

```
HTTP Chunked Stream (vLLM → API 서버)
    │
    ├─ WAV 헤더 제거 (첫 청크 44바이트)
    │
    ├─ Silence Guard (use_silence_guard=True)
    │   Leading Silence: 음성 전 무음 스킵
    │                    lookback: 버퍼에 보관했다가 실제 음성 시작 후 방출
    │   Trailing Silence:
    │     RMS < -50dB 시작 → silence_hangover_ms(100ms) 유예
    │     hangover 후 silence_duration_ms 카운트
    │     silence_duration_ms > max_silence_ms(500ms) → 스트림 종료
    │
    ├─ Tail Buffer + Cosine Fade (trailing_fade_ms > 0)
    │   마지막 fade_ms 분량 보류 → trim(-50dB) → cosine fade
    │
    └─ Trailing Silence Padding (trailing_silence_ms)
       마지막에 무음 바이트 추가
```

**EOS 침묵 총량** (기본 설정):
```
silence_hangover_ms (100) + max_silence_ms (500) = 최대 600ms
```

이 600ms가 서비스 레이어에 "near-silence PCM"으로 도착 → Early EOS Flush로 dead air 차단

## 7. 캐싱 전략

### 캐시 계층

```
L1: 세션 캐시 (전체 요청)
    Key schema: batch_voice_guard_v7 / stream_voice_guard_v5 / ws_voice_guard_v7
    포함: engine, text, voice_id, speed, temp, top_p,
          use_itn, use_icl, use_normalize, use_split,
          language, itn_domain, initial_codec_chunk_frames,
          high_fidelity, smart_prosody, hardware_profile,
          use_silence_guard, use_silence_lookback, use_micro_fade,
          trailing_silence_ms, trailing_fade_ms,
          max_silence_ms + silence_hangover_ms (silence_guard=True 시),
          max_sentence_audio_ms, eos_suffix,
          style_instruction, itn_version, voice_version,
          supertonic_style + total_steps (engine=supertonic 시만)
    ※ stream_voice_guard_v5 예외: max_silence_ms / silence_hangover_ms /
          max_sentence_audio_ms / eos_suffix 미포함.
    ※ stream / ws 공통: use_normalize=False 고정 (batch는 요청값 그대로).
    TTL: cache_ttl_seconds (기본 3600s)

L2: 문장 캐시 (개별 문장)
    Key schema: sentence_voice_guard_v8  (batch — 합성 중 inline 저장)
                sentence_voice_guard_v7  (stream / websocket — 읽기 전용)
    ※ sentence_voice_guard_v7은 services/precache_service.py가 사전 저장
       stream.py / websocket.py는 합성 중 L2를 쓰지 않음 (읽기만 함)
    기반: L1과 동일 파라미터, 단 단일 문장(sent) 기준
    공통 고정값: use_itn=False / use_normalize=False (전처리 완료)
                high_fidelity=False / hardware_profile='standard' / use_micro_fade=False
    ※ use_silence_guard 차이:
        sentence_voice_guard_v8 (batch): 요청값 그대로 포함
        sentence_voice_guard_v7 (stream/WS/precache): False 고정
    ※ use_silence_lookback 차이:
        batch L2: 요청값 그대로 / stream L2: 요청값 그대로
        WS L2 / precache: False 고정 (전달 안 함 → 기본값)
        → use_silence_lookback=True 스트림 요청은 precache L2 미스 가능
    저장 조건 (batch inline): 크기 > 1000B + silent_collapse 미감지 + voice_fallback 없음
```

### 캐시 무효화 조건

| 조건 | 처리 |
|---|---|
| `bypass_cache=True` | 캐시 쓰기/읽기 모두 건너뜀 |
| `silent_probe_peak() < 104` | 무음 붕괴 의심 → 저장 안 함 |
| voice_fallback 발생 | 잘못된 voice 캐싱 방지 |
| WS 부분 오디오 | producer 예외 / mid-stream 큐 타임아웃(`_producer_timed_out`)으로 조기 종료 시 `_can_cache=False` — sentence0 부분 오디오가 전체텍스트 키로 캐싱돼 TTL 내내 잘린 오디오 서빙되던 것 방지 |
| 누적 버퍼 초과 | WS: 100MB(`_CappedBytearray._MAX`) — 이후 청크 드롭(불완전 저장). Stream: 30MB(`max_accumulate_size_mb`) — 캐싱 비활성 |
| 문장 크기 ≤ 1000B | 너무 짧음 |

### Dedup Lock (중복 합성 방지)

동일 요청 동시 중복 합성 방지. Batch와 WebSocket에만 있음 (Stream 없음).

```python
# Batch: L1 캐시 키 그대로 락 명으로 사용, timeout=max(30, min(120, vllm_timeout/2))
async with redis_lock(key, timeout=_lock_timeout):
    if cached: return cached   # 락 후 재확인
    result = await synthesize()
    await redis_client.setex(key, ttl, result)

# WebSocket
async with redis_lock(f"ws_synth:{key[-16:]}", timeout=60, wait=0.5):
    if cached: return cached   # 락 후 재확인
    result = await synthesize()
```

## 8. 할당량 관리 (Quota)

**Key**: `user:quota:{username}:mem` (TTL 3600s, 단위: 바이트)

### Batch 흐름

```
1. 예약  check_and_reserve_quota(estimated_bytes)
         → Lua 원자 실행: 한도 확인 → OK이면 Redis INCRBY(estimated) → 초과 시 -1 반환 → 429
2. 합성
3. 정산  settle_quota(actual_bytes)
         → delta = actual - reserved → Redis INCR(delta)
         → 초과 시 rollback → 429
```

### Stream/WebSocket 흐름

```python
class StreamQuotaTracker:
    buffer = 0
    flush_threshold = 65536  # 64KB마다 Redis 반영

    async def add_bytes(n) -> bool:
        buffer += n
        if buffer >= flush_threshold:
            return await flush()   # False → 한도 초과 → 중단
        return True

    async def finalize():
        if buffer > 0: INCR(quota_key, buffer)  # 세션 종료 시 잔여 처리
```

## 9. Fallback 및 Circuit Breaker

### vLLM Circuit Breaker

```
vLLM 부하 초과  → 미들웨어 Lua → Redis "circuit_breaker:open" SET (active≥open_limit)
                                  active<close_limit 되면 Lua가 자동 DEL
vLLM 엔진 장애  → trigger_vllm_fallback() → Redis "vllm:fallback_open" SET (TTL 90s)
                  (연결 실패·0-duration 오디오 감지 시 vllm_batch/stream.py에서 자동 호출)
    │
    ▼ resolve_engine_for_request() — 두 키 OR 체크
    qwen_st_* voice  → supertonic_* 로 voice_id/engine swap, _engine_fallback=True
    그 외 voice      → engine 변경 없음 (circuit_breaker:open이면 check_synthesis_guards가 503 반환)
```

### Supertonic Circuit Breaker

```
주소별 실패 3회 → "supertonic:circuit:{addr}:open" (TTL 120s)
복구 60s 대기 후 재시도
```

### Voice Fallback

```
voice_id 미등록 OR 엔진 불일치
    → _voice_fallbacks["_last"] 기록
    → 응답 헤더: X-Voice-Fallback, X-Voice-Fallback-From
    → 해당 결과 캐시 저장 금지 (오염 방지)
```
