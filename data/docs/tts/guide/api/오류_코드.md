# API Error Codes

외부 클라이언트가 프로그래밍 방식으로 에러를 분류하고 재시도를 결정하기 위한 표준 카탈로그.

## 응답 스키마

모든 에러 응답(JSON)은 다음 필드를 포함합니다:

```json
{
  "detail": "사람이 읽는 메시지 (locale 변경 가능)",
  "error_type": "AppException 클래스명 (디버깅용)",
  "code": "고정 식별자 (이 문서 참조)",
  "retryable": true,
  "request_id": "req-uuid"
}
```

- **`detail`**: 메시지 문자열. 운영 환경에 따라 한국어/영어가 다를 수 있음. 비교 금지.
- **`code`**: contract의 일부. 변경 시 deprecation 공지. **클라이언트 분기는 이 필드를 기준으로**.
- **`retryable`**: `true`면 동일 요청 재시도 가능. `false`면 입력 변경 또는 운영자 개입 필요.
- **`request_id`**: 서버 로그 추적용. 운영팀 문의 시 함께 전달.

추가로 가능한 응답 헤더:

- **`Retry-After`** (초 또는 HTTP date): 재시도 권장 대기 시간. 429/503 응답에 함께 옴. **클라이언트는 반드시 이 값을 존중**.
- **`X-Request-ID`**: `request_id`와 동일 값.
- **`X-Engine`** (성공 응답 시, v0.8.0~): `vllm` \| `supertonic` (캐시 히트 시 `(cached)` 접미사).
- **`X-Engine-Fallback`** (v0.8.0~): `true` 시 vLLM CB OPEN/포화로 Supertonic으로 자동 swap됨을 표기.
- **`X-Engine-Fallback-Reason`** (v0.8.0~): `circuit_breaker_open` \| `vram_backpressure` \| `instance_unhealthy` 등.

## 코드 카탈로그

| Code | HTTP | Retryable | 의미 | 클라이언트 권장 처리 |
|---|---|---|---|---|
| `AUTH_INVALID` | 401 | ❌ | 토큰 형식 잘못, 키 미존재 | 재로그인/키 재발급 |
| `AUTH_EXPIRED` | 401 | ❌ | JWT 만료 | refresh 토큰으로 갱신 후 재요청 |
| `AUTH_FORBIDDEN` | 403 | ❌ | 인증 OK지만 권한 부족 (admin 전용 등) | 관리자에게 권한 요청 |
| `INPUT_INVALID` | 422 | ❌ | Pydantic 검증 실패, max_length 초과 등 | 입력 수정 |
| `NOT_FOUND` | 404 | ❌ | voice_id/리소스 미존재 | 입력 확인 |
| `RATE_LIMITED` | 429 | ✅ | per-user 시간당 한도 초과 | `Retry-After` 후 재시도. 백오프 권장 |
| `ENGINE_OVERLOAD` | 503 | ✅ | CB OPEN, 동시 채널 한도 도달 (v0.8.0+ Supertonic fallback 미적용 또는 양 엔진 모두 포화 시) | 지수 백오프(0.5s, 1s, 2s, 4s) 재시도, 최대 3회 |
| `ENGINE_UNAVAILABLE` | 503 | ✅ | 워커 다운, warmup 중 (`/health`의 `engine_warmup.{vllm\|supertonic}=pending`) | `Retry-After` 후 재시도. `/health`로 확인 권장 |
| `ENGINE_TIMEOUT` | 504 | ✅ | 합성 timeout (>300s) | 입력 길이 줄여서 재시도 |
| `ENGINE_ERROR` | 502 | ❌ | 워커가 비재시도 에러 반환 (Invalid voice, malformed payload) | request_id로 문의 |
| `MODEL_COLLAPSE` | 502 | ✅ | 확률적 무음 붕괴 — 드물게 특정 문장이 0바이트로 붕괴(모델 확률 이슈) | 자동 재시도로 대부분 완화. 반환 시 재시도 |
| `MAINTENANCE` | 503 | ✅ | 점검 모드 ON | `Retry-After` 후 재시도, 또는 운영팀 공지 확인 |
| `DB_ERROR` | 500 | ❌ | DB 일시 장애 | 운영팀 문의 |
| `INTERNAL_ERROR` | 500 | ❌ | 분류 안 된 서버 에러 | request_id로 문의 |

## 재시도 전략 예시

### Python

```python
import httpx
import time

RETRY_BACKOFF = [0.5, 1.0, 2.0, 4.0]   # 초, 최대 4회

def synthesize_with_retry(client, payload, max_attempts=4):
    for attempt in range(max_attempts):
        resp = client.post("/v1/tts/synthesize", json=payload)
        if resp.status_code == 200:
            return resp
        try:
            err = resp.json()
        except Exception:
            err = {"code": "INTERNAL_ERROR", "retryable": False}
        if not err.get("retryable"):
            raise RuntimeError(f"Non-retryable: {err}")
        if attempt + 1 >= max_attempts:
            raise RuntimeError(f"Max retries exhausted: {err}")
        wait = float(resp.headers.get("Retry-After", RETRY_BACKOFF[attempt]))
        time.sleep(wait)
    raise RuntimeError("unreachable")
```

### JavaScript (fetch)

```js
async function synthesizeWithRetry(payload, maxAttempts = 4) {
  const backoff = [500, 1000, 2000, 4000];
  for (let i = 0; i < maxAttempts; i++) {
    const resp = await fetch("/v1/tts/synthesize", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(payload),
    });
    if (resp.ok) return resp;
    const err = await resp.json().catch(() => ({ code: "INTERNAL_ERROR", retryable: false }));
    if (!err.retryable) throw new Error(`Non-retryable: ${err.code}`);
    if (i + 1 >= maxAttempts) throw new Error(`Max retries: ${err.code}`);
    const wait = Number(resp.headers.get("Retry-After")) * 1000 || backoff[i];
    await new Promise((r) => setTimeout(r, wait));
  }
}
```

## Anti-pattern (하지 말 것)

- **`detail` 문자열 매칭으로 분기**: locale 변경 시 깨짐. 항상 `code`로 분기.
- **`error_type` 의존**: 내부 클래스명이라 리팩토링 시 변경 가능. 안정성 보장 X.
- **5xx 무한 재시도**: `retryable=true` 응답에도 지수 백오프 + 최대 횟수 제한 필수.
- **Retry-After 무시**: 서버가 제시한 시간보다 일찍 재시도하면 다시 503.

## 변경 정책

- 신규 code 추가: 마이너 변경 — 클라이언트는 unknown code 받으면 `retryable` 필드로 판단.
- code 의미 변경/삭제: **breaking change** — 6개월 전 deprecation 공지 (응답 헤더 `Deprecation`, `Sunset`).
- `retryable` 값 변경: minor (false → true는 호환, true → false는 breaking으로 간주).
