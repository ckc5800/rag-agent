# Qwen3-TTS 합성 파라미터 레퍼런스 (v0.9.8)

음성 합성 API의 모든 요청 파라미터를 한 곳에 정리한 단일 출처 문서.

## 단일 출처

- **Pydantic 스키마**: [`SynthesizeBody`](../qwen3-tts-api/routers/synthesize.py#L95) (`POST /v1/tts/synthesize`, `/v1/tts/synthesize/stream`)
- **대화 모드**: ⚠️ **제거됨** (commit 4b44f47, 2026-07-02) — `DialogueSynthesizeBody`/`POST /v1/tts/dialogue` 코드 삭제. 프론트 `dialogueMode` 토글 UI는 남아있으나 백엔드 엔드포인트 없음. §11 참조
- **WebSocket**: 동일한 키를 JSON dict로 받음 (`/v1/tts/ws`, `/v1/tts/synthesize/ws`)
- **글로벌 기본값**: [`db/manager.py:_SETTINGS_DEFAULTS`](../qwen3-tts-api/db/manager.py#L761)
- **코드 기본값**: [`tts_config.py:AudioSettings`](../qwen3-tts-api/tts_config.py#L118)

## 기본값 우선순위

```
요청 body 명시값  >  DB global_settings (런타임 권위)  >  코드 _SETTINGS_DEFAULTS (시드·fallback)
```

런타임 읽기는 **코드 기본값 위에 DB 값을 덮어쓴다(DB overlay)** — `load_settings()`가 `data = dict(코드기본값)` 으로 시작해 DB 행으로 `data.update()` 하므로, **DB에 키가 있으면 DB가 우선**([db/repositories/sql_repos.py:132](../../qwen3-tts-api/db/repositories/sql_repos.py#L132)). 요청에서 `null`/미지정 시 이 계층으로 fallback. 관리자가 `/v1/admin/settings`로 바꾸면 즉시 반영(Redis pub/sub, 재시작 불필요).

> **본 표의 기본값 = "지금 신규 배포하면 나오는 값"** 이다. 신규 배포는 DB가 비어 있어 코드 `_SETTINGS_DEFAULTS`([db/manager.py:905](../../qwen3-tts-api/db/manager.py#L905))가 **그대로 DB에 시드**되므로 *표값 = 코드 기본값 = 초기 DB 값*으로 일치한다. 이후 운영자가 admin에서 바꾸면 **그때부터 DB가 권위**가 되고, **코드 기본값을 바꿔도 기존 배포는 재시드하지 않는다**(`updated_at` 존재 시 skip — [manager.py:250](../../qwen3-tts-api/db/manager.py#L250)). 따라서 기본값 변경은 ① 신규 배포면 코드(`_SETTINGS_DEFAULTS`) ② 기존 배포면 `/v1/admin/settings`(DB) 로 해야 한다. (`_SETTINGS_DEFAULTS`에 없는 키 — `stream_chunk_size`·`synth_rate_limit_per_hour` 등 — 는 `tts_config.py`가 fallback.)

## 1. 텍스트 · 음성 · 언어 (식별·라우팅)

| 파라미터 | 타입 | 기본 | 범위 | 엔진 | 설명 |
|---|---|---|---|---|---|
| `text` | string | **(required)** | 1~5000자 | both | 합성 텍스트. 초과 시 400. |
| `voice_id` | string \| null | `default_voice_id` | 영숫자·`_-`, ≤64자 | both | 화자 ID. `supertonic_*` 접두사면 Supertonic 자동 라우팅. |

| `engine` | string \| null | (자동 추론) | `vllm` \| `supertonic` | both | 명시 시 자동 라우팅 무시. |

## 3. vLLM 전용

| 파라미터 | 타입 | 기본 | 범위 | 설명 |
|---|---|---|---|---|
| `use_icl` | bool | `default_icl=true` | - | In-Context Learning(음성 클로닝). platform default는 **ON** (v0.9.6+). ref_audio가 있는 voice는 클로닝 자동 적용; ref_audio 없는 voice는 no-op. ICL 비활성화 필요 시 명시적으로 `false` 전달. |
| `use_silence_guard` | bool | `default_use_silence_guard=true` | - | 환각/반복 방지 후미 무음 감지. platform default는 **ON** (v0.9.8+, silence/noise loop 자동 stop). `silence_hangover_ms`+`max_silence_ms` 조합으로 false-positive 차단. 비활성 필요 시 명시적 `false`. |
| `use_silence_lookback` | bool | `default_use_silence_lookback=true` | - | 50ms lookback 버퍼로 첫 음절 자음 보존. 2026-06-18: false→true (sentence 끝 음절 보호). |
| `high_fidelity` | bool | `default_high_fidelity=true` | - | 고음질 DSP. Batch=vocoder 24→48kHz, Stream=실시간 path. |
| `smart_prosody` | bool | `default_smart_prosody=false` | - | 구두점 기반 자연 운율. |
| `initial_codec_chunk_frames` | int \| null | `default_initial_codec_chunk_frames=2` (07-28 확정) | 1~64 | 첫 청크 프레임 수. TTFB↓·청크오버헤드↑ 트레이드오프 — 0.6B 실측 2가 최적(1은 바닥 지배로 무익). **서버 env 전용**(`TTS_DEFAULT_INITIAL_CODEC_CHUNK_FRAMES` — DB 키 아님·admin PATCH 는 조용히 무시됨, `SynthesizeBody`에도 없음). |
| `style_instruction` | string \| null | `null` | 최대 500자 | 자연어 말투/감정 지시문. Qwen3-TTS `instructions` 파라미터로 직접 전달. 예: `"매우 활기차고 열정적으로 말해주세요."`. Supertonic은 무시. **※ 현재 엔진이 `Qwen3-TTS-12Hz-0.6B-Base` 라 영향이 매우 적음** — Base 는 화자 임베딩만 반영하는 변형으로 자연어 감정 지시는 설계상 거의 무시 (모델 카드 + 자체 청취 테스트 확인). 자세한 모델 가능범위는 [서비스_설명서 §2](../../서비스_설명서.md#2-모델-가능범위) 참조. |

## 6. 무음 / 패딩

v0.9.8: silence_guard 기본 ON 전제로 빠른 stop 튜닝 — 무음 자동 감지로 hallucination 즉시 차단.

> ⚠️ **요청 body로 조절 가능한 것은 `silence_padding_ms`·`trailing_silence_ms`·`max_silence_ms` 3개뿐**이다(`SynthesizeBody` 필드). `silence_hangover_ms`·`max_sentence_audio_ms`·`trailing_fade_ms`·`inter_sentence_padding_ms`는 **DB 설정(default_*) 전용**으로 스키마에 없어 per-request 조절 불가 — 관리자 `/v1/admin/settings`(또는 Admin 패널)로만 변경된다.

| 파라미터 | 타입 | 기본 | 범위 | 엔진 | 설명 |
|---|---|---|---|---|---|
| `silence_padding_ms` | float \| null | `default_silence_padding_ms=200` | 0.0~2000.0 | both | **시작 전** 무음 패딩(leading). cold-start glitch 완화. |
| `trailing_silence_ms` | float \| null | `default_trailing_silence_ms=50` | 0.0~2000.0 | both | **종료 후** 무음 padding. 2026-06-18: 250→50 (sequential batch + lookback 전제, boundary 무음 단축). |
| `max_silence_ms` | float \| null | `default_max_silence_ms=500` | 300.0~10000.0 | both | silence_guard 임계치 — 이 값 이상 trailing 무음 감지 시 stream stop. 2026-06-18: 1500→500 (sequential batch=1 전제 + lookback=true 로 sentence 잘림 없음, boundary 무음 1.5초로 단축). |
| `silence_hangover_ms` | float \| null | `default_silence_hangover_ms=100` | 20~500 | both | silence_guard trailing 카운트 시작 전 연속 묵음 유예. 2026-06-18: 300→100 (sequential 전제, boundary 단축). |
| `max_sentence_audio_ms` | float \| null | `default_max_sentence_audio_ms=30000` | 0~180000 | both | Hallucination Guard — 1문장당 최대 audio 길이. 초과 시 noise/wind loop 으로 판단하고 강제 종료 (단축 60000→30000). 0=비활성. |
| `trailing_fade_ms` | float \| null | `default_trailing_fade_ms=200` | 0~500 | both | 끝 cosine fade-out 길이. tail pop 방지. |
| `inter_sentence_padding_ms` | float \| null | `inter_sentence_padding_ms=80` | 0~2000 | both | 문장 사이 정적 길이. 2026-06-18: 120→80 (boundary 단축, Phase 2A 청감 검증). 구두점에 따라 자동 스케일 (`.` 1.4×=112ms, `?` 1.2×, `,` 0.5×). |

## 10. 자동 언어 감지 (v0.9.0~ 클라이언트 측)

> **백엔드 API body에 `auto_detect_lang` 필드는 존재하지 않음.** 감지는 100% 클라이언트(`frontend/src/lib/langDetect.ts` — tinyld 라이브러리)에서 처리하고, 결과 언어 코드를 `language` 필드에 담아 전송.

| 항목 | 위치 | 설명 |
|---|---|---|
| `default_auto_detect_lang` | DB `global_settings` | 관리자 글로벌 기본값(true). 신규 사용자/세션 초기값. |
| `tts_auto_detect_lang` | 브라우저 `localStorage` | 사용자별 ON/OFF (DB 글로벌보다 우선). |
| `detectLang(text)` | `lib/langDetect.ts` | tinyld n-gram, 31개 지원 언어 필터, 신뢰도 0.15 미만은 null. |

**호출 흐름**:
```
사용자 입력 → LangSelect(Auto 모드) → useEffect 250ms debounce → detectLang(text) → setDetectedLang(lang)
                                                                                  ↓
합성 클릭 → _detectAndReconcileLanguage(text) → setOpts(language=detected, voice_id=matched) → POST body
```

타 클라이언트(SDK·외부)는 직접 `language` 필드를 지정해야 함.

## 부록: EOS 변환 (v0.9.8+)

**문제**: vLLM-omni AR 모델이 마침표(`.`) 토큰을 EOS 신호로 학습 → 마지막 음절 잘림 빈발 (GPU 부하 시 심화).

**해결**: `prepare_engine_sentence()` 가 합성 텍스트의 마침표를 콜론으로 정규화:
- 후행 `.` / `。` → `::` (콜론 2개)
- 끝이 `:` 또는 다른 종결부호 → `::` 보장
- 결과: vLLM 모델이 EOS 조기 발화 없이 안정적으로 합성 완료
- 단일 `:` 는 부족, `:::` 는 과잉 (hallucination guard 30s 발화) — `::` 가 안정점
- **엔진단 보강**: stage config `default_sampling_params.logit_bias: {2150: -10.0}` 로 EOS 토큰(2150) 확률을 억제 — `::` 텍스트 변환과 함께 이중으로 조기 EOS 방지 (`-5.0`→`-10.0` 강화). 단 전각 쉼표(`，`) 등에서 간헐 EOS는 남음.

**문장 분할기 (`_BOUNDARY_RE`)**:
- 라틴 `.?!` 뒤 공백 필수(`\s+`) — `e.g.`, `co.kr`, `U.S.A.`, `3.14` 등 약어/도메인 보호
- 전각 `。？！` 는 공백 없이도 분할
- 결과: 영어 텍스트에서 약어 통째로 1문장 유지 → vLLM 입력 안 깨짐

**CJK 종결부호 인식**:
- `ensure_terminal_punct()` 가 ko/ja/zh 언어에서 `:` 도 종결로 인식
- 사용자가 콜론으로 끝맺어도 `.` 자동 추가 안 됨 (비일관성 제거)

이 EOS 변환은 엔진 입력 전용 — 캐시 키는 원본 sent 기준 유지.
