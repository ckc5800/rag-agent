# Qwen3-TTS Engine Parameter Guide (v0.9.8 Polish)

이 문서는 Qwen3-TTS Enterprise 엔진(vLLM + Supertonic 듀얼)의 합성 품질과 속도를 제어하는 주요 파라미터들에 대한 기술 명세 및 권장 가이드입니다.

> v0.8.0~: Supertonic 워커가 `tts-fast-a` 컨테이너로 분리됨. Supertonic 전용 옵션(`total_steps`, `style`)이 SynthesisPage UI에 추가됨.
> v0.9.0~: `trailing_silence_ms` 파라미터 신규(끝 잘림/팝 방지). 자동 언어 감지가 32개 언어 전체 지원(tinyld 기반).
> **v0.9.8~**:
> - **EOS 콜론 변환** (`prepare_engine_sentence`): 후행 `.` → `::` 정규화로 AR EOS 조기 발화 차단
> - **영어 약어 보호** (`_BOUNDARY_RE`): 라틴 `.?!` 공백 필수 → `e.g.`, `co.kr`, `U.S.A.`, `3.14` 등 통째로 1문장 유지
> - **CJK 종결부호**: ko/ja/zh 에서 `:` 도 종결로 인식 (자동 마침표 추가 방지)
> - **Silence Guard 기본 ON** + 빠른 stop 튜닝 (max_silence 700/hangover 300/trailing 250/hallucination 30s)
> - **voice ref_audio 일원화**: 호스트 `./data/voices/samples/` 단일 폴더 (vllm + api 공유 마운트)
> - **ICL 적용 언어**: default `"ko"` — 그 외 언어는 use_icl=False → 모델 native 화자 (vivian/ryan/aiden 등 9명 내장 speaker)

## 1. Core Synthesis Parameters

### ⚡ Speed (0.5x ~ 2.0x)
*   **설명**: 음성 합성 속도를 조절합니다.
*   **기술적 특징**: 엔진 레벨에서 직접 속도를 조절하므로 피치 왜곡 없이 자연스러운 배속 조절이 가능합니다.
*   **권장값**: 일반 안내방송(1.0), 빠른 정보 전달(1.2).

### ✨ Temperature (0.1 ~ 2.0)
*   **설명**: 음성의 무작위성과 운율의 변화폭을 조절합니다.
*   **기술적 특징**: 값이 높을수록 억양이 다채로워지지만 발음이 꼬일 확률이 높아지며, 낮을수록 기계적이지만 안정적인 발음을 제공합니다.
*   **권장값**: 표준(0.65, 플랫폼 기본값), 안정적 낭독(0.7), 다채로운 억양(0.9~1.0).

### 🎯 Top-P (0.1 ~ 1.0)
*   **설명**: 다음 오디오 토큰을 선택할 때 누적 확률 분포의 상위 비율을 제한합니다.
*   **기술적 특징**: 낮을수록 가장 확률이 높은 토큰들만 선택하므로 발음이 명확해지고 노이즈가 줄어듭니다.
*   **권장값**: 고품질(0.8 ~ 0.9).

## 2. Advanced Performance Tuning

### 📦 Chunk Size (4 KB ~ 128 KB)
*   **설명**: 네트워크로 전송되는 오디오 데이터의 최소 단위입니다.
*   **영향**: 
    *   **작을수록**: TTFB(첫 소리가 들리는 시간)가 단축되지만 전송 빈도가 잦아져 네트워크 오버헤드가 증가합니다.
    *   **클수록**: 전송 효율은 높아지나 첫 응답이 늦어질 수 있습니다.
*   **권장값**: 초저지연(4KB), 표준(32KB).

### 🚀 Codec Chunk Frames (6 ~ 25)
*   **설명**: vLLM 추론 엔진이 한 번에 생성하는 오디오 프레임 단위입니다.
*   **기술적 배경**: 프레임이 작을수록 첫 소리가 빨리 나오지만, 모델의 컨텍스트 이해도가 떨어져 음질이 소폭 저하될 수 있습니다.
*   **권장값**: 초고속(6), 고품질(16), 표준(12).

### 🔇 Silence Padding — leading / trailing

합성 시작·종료 시점에 무음 PCM을 삽입해 첫 음절 잘림과 끝 잘림/팝을 동시에 방지합니다.

*   **`silence_padding_ms` (leading, 기본 200ms)**
    *   합성 **시작 전** 무음. warm-start로 디코더/플레이어가 첫 프레임을 안정 디코드하도록 보장.
    *   `silence_guard` ON + trim_leading_silence 조합과 함께 사용 시 첫 자음 보호.
*   **`trailing_silence_ms` (v0.9.0~, 기본 250ms — v0.9.8 단축)**
    *   합성 **종료 후** 무음. 두 가지 효과:
        1. decoder/player가 마지막 frame을 flush할 시간 확보 → 끝의 클릭/팝 제거
        2. silence_guard가 borderline RMS chunk(자음 감쇠 등)를 잘랐을 때 체감 cutoff 완화
    *   v0.9.8 단축 (1500→250): silence_guard 기본 ON 환경에선 trailing padding 짧게 유지 → 문장 사이 무음 단축.
    *   **0으로 설정 시 비활성** (응답 latency 최소화 필요 시).
    *   적용 경로: vLLM 스트림 ([engines/vllm_stream.py:204](../../engines/vllm_stream.py#L204)), Supertonic in-process ([engines/supertonic/__init__.py:541-546](../../engines/supertonic/__init__.py#L541)), Supertonic 워커 ([supertonic_worker/main.py:213](../../supertonic_worker/main.py#L213)) — 3개 경로 모두 동일 설정 적용.
    *   env: `TTS_AUDIO__TRAILING_SILENCE_MS`, 합성 요청 body에 `trailing_silence_ms`로 per-call override.

### 🛡️ Silence Guard — Trailing-edge Behavior (v0.9.0 개선, v0.9.8 빠른 stop 튜닝)

vLLM 스트림이 `max_silence_duration_ms`(v0.9.8 default **700ms**, 단축 3000→700) 초과 trailing silence를 감지하면 break하던 동작에서, **break 직전에 trigger chunk를 yield**하도록 변경. borderline RMS chunk가 음성 꼬리를 포함한 경우에도 보존됨 ([engines/vllm_stream.py:307-310](../../engines/vllm_stream.py#L307)). silence_threshold_db는 `-40dB`(기본). `silence_hangover_ms` (default 300ms) 가 카운트 시작 전 vocal pause 보호.

v0.9.8: **`use_silence_guard` 기본 ON** — 모델 hallucination(noise/wind loop) 자동 stop. `max_sentence_audio_ms` (default 30000ms = 30s) 가 2차 안전망.

### ⚙️ 엔진 레벨 최적화 (운영 기본값)

요청 파라미터는 아니지만 합성 속도·일관성에 직접 영향을 주는 엔진 구성(`stage_config_qwen3_single_024.yaml`):

*   **FP8 Talker 양자화** (`quantization: fp8`): Talker(AR) 단계를 FP8로 양자화해 단일 GPU 처리량 개선. 보코더(Code2Wav)는 conv 기반이라 bf16 유지(FP8 불가). **양자화 변경 시 합성 캐시 flush 필수.**
*   **vLLM uni executor** (`--distributed-executor-backend uni`): mp(멀티프로세스) 직렬화 오버헤드 제거. 0.22 시절 "uni 2배(0.68→1.41 rps)"로 알려졌으나 **0.24 재분석 결과 uni 자체 효과는 ~+6%**이고, 처리량 상승분 대부분은 **0.24 네이티브 파이프라인**(Code2Wav CUDA-graph 배칭·2-stage 스케줄링)에서 온다. 상세: [벤치마크](../../reports/vllm_0.24_업그레이드_벤치마크_2026-07-13.md).
*   **EOS 억제**: `prepare_engine_sentence`의 `::` 텍스트 변환 + 엔진단 `default_sampling_params.logit_bias: {2150: -10.0}`(EOS 토큰 확률 억제) 이중 적용. 단 전각 쉼표(`，`) 등에서 간헐 조기 EOS는 남음.
*   **결정성(seed)**: 같은 텍스트는 매번 동일 오디오로 합성됨 — 이는 vLLM 엔진 레벨 `seed=0`(V1 기본)이 워커 RNG를 고정하기 때문. stage config의 `default_sampling_params.seed: 42`는 per-request 샘플링 seed 항목으로 재현성/품질의 주 레버가 아님(품질은 temperature·top_p로 조절). **online serving은 동시 배칭 시 재현성을 보장하지 않음.**
*   **단일 GPU(L40S) 처리량 천장 ≈ 3.1 rps** (vLLM 0.24, conc32 실측): 병목은 Talker의 순차 AR decode(GPU-지연 바운드). 0.22 시절엔 ~1.7 rps였다. 동시성 한도·FP8·executor는 효율을 높일 뿐 천장 자체는 수평 확장(별도 GPU)으로만 상승.

## 4. Supertonic 전용 파라미터 (v0.8.0~)

`voice_id`가 `supertonic_` 접두사로 시작하거나 `engine=supertonic` 명시 시에만 적용됩니다.

### 🎛️ Supertonic Total Steps (1 ~ 24, 기본 6)
*   **설명**: 디퓨전 추론 반복 단계 수. 값이 클수록 품질↑ 지연↑. platform default는 **6**(속도 우선).
*   **권장값**:
    *   초고속/기본 (`5~6`): 라이브 캐싱/콜센터 응답
    *   균형 (`8`): 일반 사용
    *   고품질 (`10~12`): 안내 방송/오디오북
*   **UI**: SynthesisPage Supertonic 옵션 패널 → Total Steps 슬라이더.

### 🎨 Supertonic Style (M1~M5, F1~F5)
*   **설명**: 동일 voice 내에서 음색을 미세 변형. `M*` 남성 5종 / `F*` 여성 5종.
*   **UI**: SynthesisPage Supertonic 옵션 패널 → Style Select.
*   **기본값**: 보이스 메타데이터에 정의된 값 (없을 시 `M1`).

## 5. 엔진 자동 라우팅 및 Fallback (v0.8.0~)

### 5.1 자동 라우팅 우선순위
1. `engine` 필드 명시 시 그대로 사용 (관리자/디버깅용).
2. `voice_id`가 `supertonic_` 접두사 → Supertonic으로 라우팅.
3. `language`가 vLLM 지원 10개 외 → Supertonic으로 라우팅 (Supertonic은 22개 추가 언어 지원).
4. 위에 해당 없음 → vLLM 기본.

### 5.2 자동 Fallback
- **트리거**: vLLM Circuit Breaker OPEN, VRAM 포화, 또는 인스턴스 unhealthy.
- **조건**: `TTS_SUPERTONIC__FALLBACK_ENABLED=true` (기본값).
- **동작**: 서버가 자동으로 Supertonic 워커로 swap. 클라이언트 페이로드 변경 없음.
- **voice 매핑 제약**: `qwen_st_*` voice만 fallback 대상 (`qwen_st_f1` → `supertonic_f1` 등 성별 일관 매핑). 그 외 voice(`qwen_zh/ja/cv` 등 비한국어 voice)는 Supertonic이 지원하지 않아 **fallback skip** → vLLM 그대로 라우팅(CB OPEN이므로 503 반환됨).
- **응답 헤더**: `X-Engine: supertonic`, `X-Engine-Fallback: true`, `X-Engine-Fallback-Reason: <원인>` 표기.
- **운영 끄기**: `TTS_SUPERTONIC__FALLBACK_ENABLED=false` (503 발생을 명시적으로 유지하고 싶은 경우).

### 5.3 응답 헤더 요약 (v0.8.0~)
| 헤더 | 설명 |
|------|------|
| `X-Engine` | 실제 합성 엔진 (`vllm` \| `supertonic`, 캐시 히트 시 `(cached)` 접미사) |
| `X-Engine-Fallback` | `true` 시 vLLM → Supertonic 자동 fallback 발생 |
| `X-Engine-Fallback-Reason` | `circuit_breaker_open` \| `vram_backpressure` \| `instance_unhealthy` 등 |
| `X-TTFB-MS` | 첫 바이트 지연 시간 (ms) |
| `X-RTF` | Real-Time Factor (총 추론 시간 ÷ 출력 오디오 길이) |
| `Retry-After` | 503 시 권장 재시도 간격 (초) |
