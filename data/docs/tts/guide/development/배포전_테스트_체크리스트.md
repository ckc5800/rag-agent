# 배포 전 테스트 체크리스트

## 1. 목적

코드·knob 변경 시 배포 전 수행할 테스트 항목을 정리함.
변경 범위별로 필요한 테스트 수준을 구분함.

## 2. 한 번에 전체 실행

```bash
./scripts/run_all_tests.sh                      # 기본(빠른) 전 종목 — 롱런·DAST active 제외
./scripts/run_all_tests.sh --skip dast,recovery  # 특정 항목 제외
./scripts/run_all_tests.sh --long-run-min 360    # 6시간 롱런 포함
./scripts/run_all_tests.sh --active-dast         # DAST active 스캔 포함(스테이징 전용 권장)
```

- §4~8 을 순차 실행(자원 경합 방지) 후 `run_all_<타임스탬프>/REPORT.md` 에 PASS/FAIL 표로 통합
- 연속 실행 제약 없음(2026-08-10 이후). admin/super_admin 은 메모리 quota 면제라 부하테스트가 429 에 막히지 않음 — 건수 rate limit 과 동일 정책
- 다만 `anonymous@<IP>` 로 잡히는 모드(solo)에서는 면제가 적용되지 않음. 그 경우 quota 500MB/시간(≈714건)에 걸려 regression 이 `INCONCLUSIVE` 로 빠질 수 있음 — 코드 문제가 아니므로 TTL 경과 후 재실행할 것
- 회귀(regression) baseline 이 없으면 첫 실행 시 자동 생성만 하고 비교는 다음 실행부터
- 60h 롱런·DAST active 는 기본 제외 — 각각 시간이 오래 걸리거나(수 시간) 운영 서버에 부작용 가능해 옵트인

## 4. 상시 게이트 (모든 코드 변경 시 필수)

| 항목 | 기준 |
|---|---|
| err_class 회귀 | silent·exception·429 비율이 변경 전 대비 급증 없어야 함 |
| 리소스 피크 회귀 | CPU·RES·VRAM 피크가 확정 스펙 범위 내여야 함 |
| quota 정상 동작 | 429 정상 발생 확인, 200+빈바디 재현 없어야 함 |
| 회귀(regression) | 핵심 지표(success_rate·TTFB·E2E·RTF)가 baseline 대비 악화 없어야 함 |
| UAT | 사용자 시나리오(합성·스트리밍·캐시 체감) 전부 PASS |

```bash
# err_class 회귀 — 짧은 지속 부하 (콜센터 패턴, 10분)
python3 scripts/loadtest/callcenter_realistic.py \
  --profile concurrency --agents 30 --duration-min 10 --model-tag 0.6B --tag predeploy_smoke

# 리소스 피크 회귀 — N=5/15/20/36 순간부하, 3회 반복
AGENT_LEVELS="5 15 20 36" REPEATS=3 bash scripts/spec_stress_test.sh

# quota 정상 동작 — admin UI에서 대상 계정 global_memory_quota_mb 를
# 작은 값(예: 5)으로 임시 하향한 뒤 스트림 요청 1건 발사, 429 응답 확인
# (quota 는 DB 값이 우선 적용됨 — .env.prod 수정으로는 안 됨)
API_URL="http://localhost:8210"
SECRET=$(grep '^TTS_AUTH__ACCESS_SECRET=' .env.prod | cut -d= -f2)
curl -N -X POST "$API_URL/v1/audio/speech" \
  -H "X-Access-Secret: $SECRET" -H "Content-Type: application/json" \
  -d '{"model":"qwen3-tts","voice":"F_ko_bright_f1","input":"테스트 문장입니다.","stream":true}' \
  -w "\nHTTP_STATUS=%{http_code}\n"

# 회귀 — 최초 1회 baseline 저장, 이후 실행 시 자동 비교
python3 scripts/loadtest/regression_check.py --save-baseline   # 최초 1회
python3 scripts/loadtest/regression_check.py                   # 이후 배포 전마다

# UAT — 사용자 시나리오 스모크
python3 scripts/loadtest/uat_checklist.py
```

## 5. 지속 부하 / 장시간 / 순간 폭주 (아키텍처·엔진·캐시 구조 변경 시만)

| 항목 | 기준 |
|---|---|
| 지속 트래픽 패턴 | 콜센터 실사용 간격 기준 안정 응답 확인함 |
| Spike(순간 폭주) | 100명 10초 동시 spawn 시 wave 발생은 정상, 붕괴·미회복 없어야 함 |
| 장시간 열화(메모리 누수 등) | hour-by-hour err_class 비율 평탄, drift 없어야 함 |
| 60h급 롱런 | 근거 있는 의심(캐시 만료 주기·TTL 경계 등) 있을 때만 수행함. 기본 불필요 |

```bash
# 지속 트래픽 패턴 — 수십 분
python3 scripts/loadtest/callcenter_realistic.py \
  --profile overnight --agents 30 --duration-min 60 --model-tag 0.6B --tag predeploy_pattern

# Spike — 순간 폭주 (100명 10초 동시 spawn, 5분)
python3 scripts/loadtest/callcenter_realistic.py \
  --profile burst --model-tag 0.6B --tag predeploy_spike

# 장시간 열화 — 수 시간 (예: 6시간)
python3 scripts/loadtest/callcenter_realistic.py \
  --profile overnight --agents 30 --duration-min 360 --model-tag 0.6B --tag predeploy_soak

# 60h 롱런 — 근거 있을 때만
python3 scripts/loadtest/callcenter_realistic.py \
  --profile overnight --agents 30 --duration-min 3600 --model-tag 0.6B --tag longrun60h
```

## 7. 보안 — DAST / Pen test

| 항목 | 기준 | 실행 시점 |
|---|---|---|
| DAST(동적 스캔) | ZAP passive 스캔 High/Medium 알림 없어야 함 | 상시(passive), active는 스테이징·유휴 시간대만 |
| Pen test(경계값) | 인증 우회·권한 상승·주입·과대 payload·경로 순회 전부 PASS | 인증·라우팅·입력검증 로직 변경 시 |

```bash
# DAST — passive (안전, 상시 실행 가능)
bash scripts/security/dast_scan.sh

# DAST — active (공격 payload 전송, 스테이징/유휴시간대 전용)
ACTIVE=1 API_URL=http://staging:8210 bash scripts/security/dast_scan.sh

# Pen test — 경계값 점검 (자체 시스템 대상, CI 게이트용 저비용 스모크)
python3 scripts/security/pen_probe.py --base http://localhost:8210
```

- `tests/functional/test_security.py`(pytest)가 기본 인증(토큰 회전·로그아웃 등)은 이미 커버함 — `pen_probe.py`는 그 외 경계값만 다룸
- 정식 침투테스트 엔게이지먼트가 필요하면 별도 외부 계약 진행 (본 스크립트는 대체 아님)

## 8. Migration & Recovery

| 항목 | 기준 |
|---|---|
| 백업 무결성 | 백업 파일(postgres/redis/통합 데이터)이 손상 없이 열림 |
| 복구 가능성 | postgres 덤프가 실제로 복구되어 테이블이 존재함 |

```bash
# 새로 백업부터 시작해 무결성 + 복구 드릴까지 자동 수행
# (일회용 컨테이너에만 복구 — 운영 DB/볼륨은 건드리지 않음)
bash scripts/recovery_drill.sh

# 기존 백업 디렉토리로 검증만
bash scripts/recovery_drill.sh /backup/tts/20260810_030000
```

- 실제 운영 복구(`restore.sh`)는 운영 볼륨을 덮어쓰는 파괴적 작업 — 드릴 통과 여부와 무관하게 실행 전 반드시 별도 확인함
- DB 스키마 마이그레이션은 `qwen3-tts-api/scripts/migrations/`의 개별 스크립트(ad-hoc, alembic 아님) — 배포 전 대상 스크립트를 스테이징에서 먼저 실행해 idempotent 여부 확인함
