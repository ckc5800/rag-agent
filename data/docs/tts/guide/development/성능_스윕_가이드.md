# 동시성 knob 자동 스윕 가이드 (perf_matrix)

Qwen3-TTS 의 동시성·TTFB 관련 knob 을 자동 스윕하고 SLA 별 최대 동시 N 을 판정하는 도구. **2026-07-27 스윕의 정본 도구이며, 옛 `perf_sweep.sh` (curl 지속부하 방식) 를 대체한다** — 지속부하 방식은 "동시 N 요청이 같은 순간 도착" 이라는 burst 목적과 맞지 않아 폐기.

- **위치**: `scripts/perf_matrix.sh` (오케스트레이터) · `scripts/perf_matrix_report.sh` (리포트) · `scripts/loadtest/callcenter_realistic.py` (부하 발생기)
- **실행 서버**: 배포된 TTS 서버 (157) 셸에서 직접 실행
- **의존성**: bash · curl · python3 · `nvidia-smi` · git (원복용)

> **[2026-07-28 하네스 대개편]** 07-27 스윕이 "0.6B 라벨·1.7B 실측" 오라벨로 판명된 사고 후 안전장치·계측이 대폭 추가됨. 판정 규칙·계측 해석은 `docs/reports/TTFB_최적화_0.6B_2026-07-28.md` §6 이 정본.
> - **모델 3중 검증**: 시작 시 env `VLLM_A_HF_MODEL` + 엔진 `/v1/models`(root 필드·docker exec fallback·로딩 대기 최대 25분) vs `MODEL_TAG` — 불일치 시 시작 안 함. 부하기도 `--expect-model` 로 재검증·summary 에 `served_model` 기록
> - **knob verify fail-fast**: 전 클래스에서 반영 확인 실패 시 그 값 스킵 (기존 warn-only)
> - **무효 측정 가드**: 전량 503 iter → 스윕 즉시 중단 (VRAM/CB 게이트 차단 감지). 전량 silent + SpeechE2E 0줄 = 엔진 다운 신호로 판독
> - **계측 수집**: iter 마다 엔진 `[SpeechE2E]` 구간 분해 로그(`raw/speech_e2e_*`) + vLLM `/metrics` 1초 폴링(`raw/engine_metrics_*`, host/exec 자동 판별) 저장 → 리포트에 prep/engine_first_chunk 표 자동 생성
> - **리포트 판정 강화**: SLA 최대 N 연속성 요구(스파이크로 뚫린 상위 N 채택 금지) · `†` 스파이크 마킹
> - **측정 오염 제거**: `nvidia-smi` 폴링 1s→7s(GPU stall 자기오염) · 부하기 wav 디코드 to_thread · `--warmup-requests`(동일 클라이언트·문장 웜업)
> - **`VARIED=1`**: 가변 문장 모드(코퍼스 로테이션·REPEATS 기본 5) — prefix cache 낙관 해소용 병행 측정

## 측정 모델 (burst · A-방식)

> knob 값별로 · **동시 N개 합성 요청이 같은 순간 도착**했을 때 각 요청의 TTFB 를 재고 · TTFB p95 가 SLA (500/1000/1500ms) 이내인 최대 N 을 찾는다.

- instant spawn (N개 동시 발사) · **single-shot** (agent 당 1요청) · **bypass_cache** · **고정 문장** (43자) · **고정 voice** (`F_ko_bright_f1`) — 변인 완전 통제
- 경로: `/v1/tts/synthesize/stream` (실 콜센터 데모와 동일)
- TTFB = 요청 전송 직전 → 첫 오디오 chunk (세마포어·큐 대기 포함 · 클라이언트 체감)
- 집계: 3회 반복 · `requests.csv` 합산 pooled percentile (회차별 p95 평균 아님)
- 판정: silent>0 또는 RTF p95>1.0 또는 실패 → 그 N 은 SLA 무관 탈락 (✗)

## knob 클래스 (5종)

| 클래스 | 적용 방법 | 비용 | 대상 예 |
|---|---|---|---|
| PATCH | admin API PATCH (DB) · 재기동 無 | 즉시 | 진짜 DB 키만 (주의: pydantic 이 미지 필드를 조용히 무시하고 200 반환 — verify 필수) |
| ROLL | `.env.prod` sed + `deploy-roll.sh` | ~7분 | ICF · STREAM · WORKERS · STREAM_CHUNK_SIZE · high_fidelity |
| VLLM | `.env.prod` sed + `vllm-a force-recreate` + healthy 폴링 + deploy-roll | ~20분 | MAX_NUM_SEQS(+VOC 페어) |
| YAML | stage yaml sed (bind-mount 라 재빌드 불필요) + vllm-a 재생성 | ~20분 | CODEC_LEFT_CONTEXT · CODEC_CHUNK_FRAMES · GPU_MEM · PREFIX_CACHE · DECODE_TF32 · CODE_PREDICTOR · MBT · MAX_MODEL_LEN · CONNECTOR_SLEEP |
| EXEC | native yaml 사본에서 executor 만 mp 로 바꾼 `_mp_auto.yaml` 생성 | ~20분 | EXECUTOR (uni 는 vLLM 0.24 hang — 금지) |

## 실행 방법

```bash
cd /path/to/qwen3-tts

# 단일 knob
KNOB=CODEC_LEFT_CONTEXT ./scripts/perf_matrix.sh

# 값·N 그리드·반복 override (경계 정밀용)
KNOB=CODEC_LEFT_CONTEXT VALUES="25 72" AGENT_LIST="8 10 12 15 20" REPEATS=5 ./scripts/perf_matrix.sh

# 야간 배치 (knob 순차)
nohup bash -c 'for K in MAX_NUM_SEQS CODEC_LEFT_CONTEXT ...; do KNOB=$K ./scripts/perf_matrix.sh; done' > perf_batch.log 2>&1 &
```

주요 환경변수: `KNOB` `VALUES` `AGENT_LIST`(기본 "3 5 8 10 15 20 30 50") `REPEATS`(3) `STAB_SLEEP`(120) `FIXED_VOICE`(기본 F_ko_bright_f1) `EXCLUDE_VOICES`(기본 병리 2종) `DRY=1`

## 내장 안전장치·절차

- **lockfile** (`/tmp/perf_matrix.lock` · PID 검사) — 다중 인스턴스가 .env.prod 를 교차 sed 하던 7/24 사고 재발 방지
- OUT_DIR 에 `.env.prod`·stage yaml **백업** + trap cleanup (원복 + 리포트)
- 측정 중 **BP_OPEN/CLOSE 200/160 임시 상향** (CB 오염 방지) · 종료 시 원복
- knob 적용마다 **실효값 verify** (env + DB + `ps` 워커 수 + 컨테이너 yaml) — 실패 시 그 값 skip
- iter 사이 `active_channels==0` 폴링 + warmup throwaway 10건

## 결과 판독 기준 (중요)

1. **스파이크 오염**: 산발 ~3초 단일 요청 스파이크 (knob 무관 서버 주기성 · 원인 미상) 가 무작위 셀 1~2개를 2.5~5초로 오염시킴. **앞뒤 N 이 매끈한데 중간 N 만 튀는 셀은 스파이크로 간주하고 판정에서 제외.**
2. **N≥30 의 ✗**: 대부분 세마포어 슬롯 릴리즈 마진의 429 (품질 붕괴 아님). silent 여부로 구분.
3. **voice 변인**: 반드시 고정 voice 로 비교. `F_ko_lively`·`F_ko_calm` 은 확률적 무음 붕괴 병리 — 절대 포함 금지.
4. **절대치 해석**: 고정 문장 + prefix caching 으로 낙관 편향 (상한) / burst 는 최악 도착 패턴 + bypass_cache 라 보수 편향 — 방향이 상쇄되므로 knob 간 **비교** 가 주 용도.

## 복구 절차 (배치가 비정상 종료됐거나 결과 폴더를 지웠을 때)

결과 폴더 삭제 = env 백업도 소실 → trap 원복 실패 가능.

⚠️ **`.env.prod` 는 git 추적 해제됨 (커밋 19630338 · 크리덴셜 public 미러 노출 방지)** — `git checkout .env.prod` 복구는 더 이상 불가. 복구 소스는 ① 다른 perf_matrix 폴더의 `env.prod.backup`, ② 로컬 전용 `scripts/restore_env_prod.py`. stage yaml 은 여전히 추적됨 (checkout 가능).

```bash
pkill -f perf_matrix; sleep 2; rm -f /tmp/perf_matrix.lock
cp <가장최근_정상_perf_matrix_폴더>/env.prod.backup .env.prod   # 또는 restore_env_prod.py
git checkout qwen3-tts-engine/stage_config_qwen3_single_024.yaml
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --force-recreate vllm-a
# healthy 대기 후
./scripts/deploy-roll.sh
# 확인: MAX_NUM_SEQS=48 · STREAM=36 · bp_open=56 · vram_limit=0
```

## 과거에 잡은 함정 (재발 주의)

- 부하기 config dict 에 `single_shot`/`bypass_cache` 누락 → 지속부하+캐시hit 로 측정되던 P0 (agents=3 인데 요청 15건이 지문)
- bare `wait` 가 모니터 kill 의 exit 143 을 받아 `set -e` 즉사 → `|| true`
- `initial_codec_chunk_frames` 는 admin PATCH 불가 (env 전용) — PATCH 200 응답을 믿지 말고 GET 으로 verify
- `TTS_WORKERS=8` 은 healthcheck 통과 후 부하 시점 API 다운 (원인 미조사 · 4 고정)
