### 판정 (부하별)
- ✅ **지속 부하**: 매우 안정 · 튜닝 없이 서비스 가능
- ⚠️ **극단 급증**: 시스템 안 죽음 (실패 0) · **큐 대기 지연 발생** · GPU 확장 여지

### 재현성 검증 완료
- 같은 조건 2회 실측 · **편차 ±10~65ms** (매우 안정)
- 즉 실측 지표는 우연 아니고 시스템 실 성능

## 📊 상세 지표 · 지속 저부하 (실 콜센터 기본)

### 응답 지연 (Time to First Byte)

사용자가 소리 듣기 시작하는 시점까지 걸리는 시간.

| 백분위 | 값 | 해설 |
|-----|-----|-----|
| 평균 (p50) | 103ms | 절반 이상 100ms 이내 |
| p95 | 262ms | 100건 중 95건 260ms 이내 |
| p99 | 388ms | 100건 중 99건 400ms 이내 |
| p999 | 1,078ms | 1000건 중 1건만 1초 초과 |
| max | 1,936ms | 최악 케이스 · 30분 중 유일 |

**콜센터 UX 기준**:
- < 200ms · 즉시 (자연 통화)
- < 500ms · 자연스러움
- < 1000ms · 약간 대기감
- > 1000ms · 어색함

**결과**: 대부분 400ms 이내 · 1000ms 초과는 1000건 중 1건.

### 전체 완료 (End-to-End)

첫 소리부터 마지막 소리까지 완료 시간.

| 백분위 | 값 | 해설 |
|-----|-----|-----|
| p50 | 124ms | 짧은 안내 위주 |
| p95 | 1,151ms | 긴 문장 (약관 등) 포함 |
| p99 | 2,039ms | 최장 문장 여유 |

**해석**: 스트리밍이라 사용자는 이 시간 통째로 대기 안 함. 첫 응답 후 실시간 재생.

### 처리 능력

| 지표 | 값 |
|-----|-----|
| 실측 지속 처리 rps | **5 rps** (30분 안정) |
| 최대 동시 세션 (별도 실측) | **512+** (실패 0) |
| 콜센터 5rps 처리 시 활성 세션 여유 | **매우 큼** |

**참고**: 실 콜센터 상담원 활성 세션당 초당 요청 수 미확정. 상담원 200명 통상 페이스 감안 시 충분한 여유.

## 🌐 네트워크 조건

**중요**: 실측은 sandbox(로컬 개발환경) → 스테이징 서버 원격 실행.
매 요청 **네트워크 왕복 약 40ms 포함**.

- 실 콜센터 백엔드가 **같은 데이터센터** 내부라면 → 실 지연은 지금 값에서 **40ms 줄어듦** (더 좋음)
- 실 콜센터 백엔드가 **인터넷·VPN 경유**라면 → 지금 값과 유사 or 늘어남

**결론**: 지금 지표는 **실 사용자 관점에 근사** · 배포 후 실측 재확정.

## 📋 미확정 · 후속 필요

### 실 서비스 조건 (조직·고객 협조)
1. **콜센터 시스템 IP 구조** — 게이트웨이 단일 IP or 상담원 개별 IP
2. **실 요구 SLA** — 콜센터 담당자 기준 응답 지연 허용치
3. **실 트래픽 프로파일** — 상담원당 TTS 호출 빈도 · 문장 다양성
4. **실 corpus** — 실제 안내·응대 대사 (현재 합성으로 대체)

### 실측 확장 (기술)
5. **서버 내부 실측** — 순수 서버 상한 (네트워크 40ms 제거)
6. **장기 실측** — 24시간+ · 시간대·GC·안정성 관측
7. **다중 클라이언트 실측** — 여러 IP 시뮬
8. **프로덕션 카나리** — 실 트래픽 shadow or 파일럿 팀

### 튜닝 가능성 (실측 후)
9. **vLLM 동시성 상향** — MAX_NUM_SEQS 48 → 64/96 (0.6B 여유 활용)
10. **GPU 수평 확장** — vllm-B 활성 (수요 급증 시)
11. **프리캐시** — 자주 쓰는 안내 미리 합성 (콜드 스타트 개선)

## 🔬 실측 방법론 (기술 근거)

### 부하 스크립트
- 파일: `docs/internal/reviews/preprod/06b_ab/callcenter_realistic.py`
- 프로파일: smoke · warmup_only · callcenter · **sustained (이번 실측)** · burst · ramp_up · overnight
- 재현 명령: `python callcenter_realistic.py --profile sustained --model-tag 0.6B`

### 합성 corpus
- 파일: `docs/internal/reviews/preprod/06b_ab/corpus/callcenter_synthetic.json`
- 215 문장 · 6 카테고리 (인사·환송·안내·약관·응대·번호)
- Length bucket: short (< 30자) · medium (30~120자) · long (120자+)
- 개인화 placeholder (`{name}·{phone}·{account}·{amount}·{date}·{code}·{ref}`)

### 서버 설정 (실측 조건 스냅샷)
- 후처리 (guard): 서버 default (실 사용자와 동일 조건)
- 동시성: batch=16 · stream=32 (튜닝 X)
- 백프레셔: mem 95% · vram 9.4GB (튜닝 X)
- vLLM: MAX_NUM_SEQS=48 · fp8 · uni executor
- 자세한 실효값은 `summary.json._meta.server_snapshot` 참조

### 관측 제약 (한계 명시)
- vLLM 내부 지표 (KV cache · GPU util · queue) 외부 노출 안 됨
- Sandbox 에서 `nvidia-smi` · `docker stats` 접근 불가
- TTFB tail 원인 (GPU vs CPU vs 네트워크) 분리 미확정
- 필요 시 서버 내 관측 병렬 실행 별도 세션
